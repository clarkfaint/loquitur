# features.md — Lectern architecture brief

**Lectern** is the working codename for a clean-room, open-source, single-user read-aloud system with feature parity to the reading features of a commercial read-aloud app (the *reference product*). The reference product is not named anywhere in this repository.

- Clients: Web app, Chrome extension, Desktop (Windows + Linux), Android.
- One self-hosted **hub** does parsing, OCR, speech synthesis, AI summaries, and sync.
- One user. No accounts, no tenants, no billing, no telemetry, no third-party cloud.

Section numbers in this file are stable. `spec.md` cites them as `F§n.n`.

---

## 1. Design principles

| # | Principle | Consequence |
|---|---|---|
| P1 | **The hub does the heavy work; clients are players.** | PDF/EPUB/DOCX parsing, OCR, TTS, and LLM calls run in one Node process. No client re-implements them. |
| P2 | **One document model, one tokenizer.** | Every platform addresses text as `(docId, sentenceIndex, wordIndex)`. Positions are portable across devices by construction. |
| P3 | **The sentence chunk is the unit of audio.** | Each sentence is synthesized once, content-addressed, cached forever, and carries its own word timings. Sentence boundaries are exact; only intra-sentence word timing can drift. |
| P4 | **Local-first.** | Each client owns a `LibraryStore` and a `BlobCache`. Everything opened once works offline. Sync (Phase 5) is layered on, never required. |
| P5 | **Interfaces with conformance suites.** | `TtsEngine`, `AudioQueueSink`, `LibraryStore`, `BlobCache`, `OcrEngine`, `LlmProvider` each ship a shared test suite that every implementation must pass. The executor implements *to a test*, not to a description. |
| P6 | **A mock engine makes everything testable.** | A deterministic `mock` TTS engine and a mock LLM server let every unit be verified with no GPU, no Docker, and no network. |
| P7 | **TypeScript only.** | No Rust, no Kotlin, no Swift, no Python in this repository. Native Android code is generated by Expo config plugins and never hand-edited. |

### 2.2 Why these, and what was rejected

| Decision | Rejected alternative | Why rejected |
|---|---|---|
| **Electron** for Desktop | Tauri v2 | Tauri adds Rust and a second IPC model. Hotkeys, tray, file watching, and screen capture are single documented Node/Electron calls. Electron loads the web build unchanged, so Phase 3 writes only OS-integration code. |
| **Expo** for Android | Tauri mobile, Capacitor, native Kotlin | First-party Expo modules cover background audio with lock-screen controls (`expo-audio`), share-sheet receive (`expo-sharing`), SQLite, and files. Config plugins replace hand-edited Gradle and manifests. WebView-based audio (Capacitor/Tauri) is unreliable in the background. Kotlin would share no code. |
| **`expo-audio`** for playback | `@rntp/player` (react-native-track-player v5) | v5 is commercially licensed, so it does not meet the open-source requirement. `expo-audio` `AudioPlaylist` provides a native queue, lock-screen controls, and rate control. |
| **Hub-side synthesis** | On-device TTS in each client | Four engine integrations (WASM, Node, Android native) versus one HTTP adapter. Offline use is covered by caching and a "download for offline" action (F§10.1, F§10.4). |
| **Hand-rolled tokenizer** | `Intl.Segmenter` | ICU data differs between V8, Node, and Hermes. Different segmentation on two devices would break synced positions. |
| **CSS Custom Highlight API** | Wrapping words in `<span>` | Highlighting must not mutate third-party page DOM in the extension. |
| **Offscreen document** for extension audio | Audio in the content script | Page CSP can block media in content scripts, and MV3 service workers cannot play audio. |
| **Record-level last-writer-wins** sync | CRDTs | One user, a handful of devices, small records. |

## 5. Core engine — `packages/core`

### 5.1 Document model

```ts
type SourceKind = 'pdf' | 'epub' | 'docx' | 'txt' | 'html' | 'url' | 'ocr' | 'selection' | 'summary';
type BlockKind  = 'heading' | 'paragraph' | 'list-item' | 'quote' | 'caption'
                | 'header' | 'footer' | 'footnote';

interface DocumentModel {
  schemaVersion: 1;
  tokenizerVersion: 1;
  docId: string;             // F§5.2
  title: string;
  lang: string;              // BCP-47, default 'en'
  source: { kind: SourceKind; uri?: string; mime?: string; pageCount?: number };
  blocks: Block[];
  sentenceCount: number;
  wordCount: number;
}
interface Block {
  index: number;             // 0-based, document order
  kind: BlockKind;
  level?: 1 | 2 | 3 | 4 | 5 | 6;   // headings only
  page?: number;             // 1-based, paged sources only
  skip: boolean;             // true for header / footer / footnote furniture
  text: string;              // normalized
  sentences: Sentence[];
}
interface Sentence {
  index: number;             // GLOBAL 0-based index across the document
  blockIndex: number;
  charStart: number;         // offsets into Block.text, end exclusive
  charEnd: number;
  text: string;
  words: Word[];
}
interface Word {
  index: number;             // 0-based within the sentence
  charStart: number;         // offsets into Sentence.text, end exclusive
  charEnd: number;
  text: string;              // includes attached punctuation
}
interface Position { docId: string; sentenceIndex: number; wordIndex: number }
interface PdfAnchor { sentenceIndex: number; wordIndex: number; page: number;
                      itemIndex: number; charStart: number; charEnd: number }
```

Every type has a zod schema with the same name suffixed `Schema`.

### 5.2 Normalization and identifiers

`normalizeText(s)`: Unicode NFC → `\r\n` and `\r` to `\n` → replace U+00A0 with a space → remove U+00AD → collapse runs of spaces and tabs to one space → trim each line → collapse 3+ newlines to 2 → trim.

`docId = sha256Hex(utf8(blocks.map(b => b.text).join('\n'))).slice(0, 32)`

Golden values (the executor's tests must assert these):

| Input | Value |
|---|---|
| `docId` for one block `Hello, world.` | `f8c3bf62a9aa3e6fc1619c250e48abe7` |
| `docId` for blocks `Title` and `Hello, world. Second sentence here.` | `684c0459dd47803dec1ee32224195049` |

### 5.3 Tokenizer (tokenizerVersion 1)

Deterministic, hand-rolled, no `Intl.Segmenter`, no locale data.

**Sentences.** Scan a block's text left to right. A *candidate boundary* is a terminator run `[.!?…]+` followed by any closers `["')\]”’»]*`, then whitespace, then a character that is an uppercase letter, a digit, or an opener `["'(\[“‘«]`. A candidate is **rejected** when the terminator is a single `.` and the token immediately before it (letters and inner dots only) is:

1. in the **case-insensitive** set (tokens that are not ordinary words): `mr mrs ms dr prof sr jr vs etc e.g i.e fig eq vol pp cf approx dept inc corp ltd llc u.s jan feb apr jun jul aug sep sept oct nov dec`, or
2. in the **exact-case** set (tokens that are ordinary words when lowercase, so only this spelling counts): `St No Mar Co Ed Est Art App Cal Ch Sec Id Op Ct Rev Stat Supp Cir Rptr al`, or
3. a single letter (an initial as in `J. K. Rowling`, or the `v.` of a case name).

The exact-case set carries the legal-citation abbreviations (`Art.`, `Sec.`, `Cal.`, `App.`, `Supp.`, `Cir.`, `Ct.`, `Id.`), so that `Open the app.` still ends a sentence while `Cal. App. 4th` does not.

The end of the block always ends a sentence. A sentence longer than 400 characters is split at the last `,` `;` `:` or `—` at or before character 400, otherwise at the last space at or before 400. Leading and trailing whitespace is excluded from sentence ranges.

**Words.** A word is a maximal run of non-whitespace characters. A run with no letter or digit (for example `—`) is merged into the preceding word's range, or into the following word if it is first.

Known limit, accepted: an abbreviation that truly ends a sentence (`…in the U.S. He left.`) does not split. The tokenizer errs toward fewer splits.

Golden cases (must be asserted verbatim):

| Input | Sentences |
|---|---|
| `Dr. Smith went to Washington. He arrived at 3.15 p.m. on Jan. 5.` | `Dr. Smith went to Washington.` / `He arrived at 3.15 p.m. on Jan. 5.` |
| `In Roe v. Wade, 410 U.S. 113 (1973), the Court ruled. See id. at 115.` | `In Roe v. Wade, 410 U.S. 113 (1973), the Court ruled.` / `See id. at 115.` |
| `Wait... what? Yes!` | `Wait... what?` / `Yes!` |
| `She said, "Stop." Then she left.` | `She said, "Stop."` / `Then she left.` |
| `J. K. Rowling wrote it.` | one sentence |
| `Open the app. Then read Art. 5 aloud.` | `Open the app.` / `Then read Art. 5 aloud.` |

### 5.4 Parsers — `@lectern/core/parsers` (Node only)

Every parser returns `RawBlock[]` (`{ kind, level?, page?, text, anchors? }`) and metadata. `buildDocument(rawBlocks, meta)` normalizes, classifies `skip`, tokenizes, and assigns indexes and `docId`.

| Format | Library | Rules |
|---|---|---|
| TXT / Markdown | none | Blank line separates paragraphs. `#`…`######` are headings. `-`, `*`, `1.` start list items. `>` starts a quote. Inline markdown markers are stripped. |
| HTML / URL | `@mozilla/readability` + `linkedom` | Article extraction, then map `h1–h6`, `p`, `li`, `blockquote`, `figcaption`. Fallback when Readability returns null: all block-level text under `body`. |
| PDF | `pdfjs-dist` legacy build | Text items are grouped into lines by baseline, and lines into paragraphs by vertical gap > 1.5× the median line height. A line ending in `-` followed by a lowercase start is de-hyphenated. A font size ≥ 1.25× the page median marks a heading. Each word records a `PdfAnchor`. |
| EPUB | `fflate` + `linkedom` | Read `META-INF/container.xml` → OPF → spine order. Each spine XHTML is mapped like HTML. `nav` and cover documents are dropped. |
| DOCX | `mammoth` | `convertToHtml`, then the HTML mapping. |
| Image / scanned PDF | `tesseract.js` | F§5.5. |

**Skip classification** (`classifySkip`): for paged sources, a line whose text, with digits replaced by `#`, appears in the top 8% or bottom 8% of at least 60% of pages (minimum 3 pages) is `header` or `footer` with `skip: true`. A block starting with a footnote marker (`^\d{1,3}[.)]?\s` in a font smaller than 0.85× the page median, or below a horizontal rule) is `footnote` with `skip: true`. Skipped blocks stay in the model and are omitted from playback only when the `skipFurniture` setting is on (default on). When `skipCitations` is on (default off), bracketed numeric citations such as `[12]` or `[3, 4]` are removed from the text sent to synthesis; the document text is not changed.

**Dispatcher** (`parseDocument(input)`): sniff magic bytes first (`%PDF`, `PK` + `mimetype` entry for EPUB, `PK` + `word/document.xml` for DOCX, PNG/JPEG/WebP signatures), then the declared MIME type, then the file extension. Unknown input is treated as UTF-8 text when it decodes without replacement characters; otherwise the call fails with `UNSUPPORTED_FORMAT`.

### 5.5 OCR pipeline

```ts
interface OcrEngine {
  id: string;
  recognize(image: Uint8Array, opts: { lang: string }):
    Promise<{ lines: { text: string; bbox: [number, number, number, number]; confidence: number }[] }>;
}
```

- Hub adapter: `TesseractOcrEngine` (`tesseract.js`, language data cached under the data directory).
- Lines are grouped into paragraphs by a vertical gap > 1.5× the median line height. Lines with confidence < 40 are dropped.
- Scanned PDF fallback: a PDF page with fewer than 20 extracted characters is rasterized at 200 DPI with `pdfjs-dist` + `@napi-rs/canvas` and passed to the OCR engine. The result has `source.kind = 'pdf'`; OCR'd pages carry no `PdfAnchor`.
- Android does not use this pipeline for the camera. It runs ML Kit on-device and builds the document locally with `buildDocument` (F§10.4).
- PaddleOCR is an allowed future `OcrEngine` adapter. It is not built in this spec.

### 5.6 Timing and synchronization math

All times are integer milliseconds of **media time** within one chunk. Media time is independent of playback rate, so no rate correction is ever applied to timings.

```ts
interface WordTiming { i: number; s: number; e: number }   // word index, start, end
```

**(a) Estimated timings** — `estimateTimings(words, durationMs)`, used when an engine returns no timestamps:

- `alnum(w)` = number of letters and digits in the word, minimum 1.
- `pause(w)` = 3 if the word ends with `.`, `!`, `?` or `…` (ignoring closers); 2 if it ends with `,`, `;`, `:` or `—`; otherwise 0.
- `weight(w) = alnum(w) + pause(w)`, `W = Σ weight`, `P(i) = Σ weight(k) for k < i`.
- `s(i) = round(D · P(i) / W)`, `e(i) = round(D · (P(i) + alnum(i)) / W)`.

Golden: words `Hello,` `world.` with `D = 1000` → `[{i:0,s:0,e:333},{i:1,s:467,e:800}]`.

**(b) Aligning engine timestamps** — `alignEngineTimings(words, engineTokens, durationMs)`. Engine tokens are `{ text, s, e }` in milliseconds.

1. `norm(x)` = lowercase, keep Unicode letters and digits only.
2. Walk words and engine tokens with two monotonic pointers. For word `w`, concatenate consecutive engine tokens while the concatenation is a prefix of `norm(w)`. On equality the word is *matched*: `s` = first token's start, `e` = last token's end. Engine tokens whose `norm` is empty are skipped.
3. On mismatch, the word is *unmatched*; the token pointer advances by at most 3 tokens to look for a token that starts `norm(next word)`, otherwise it stays.
4. Each run of unmatched words is filled by `estimateTimings` over the gap between the neighbouring matched words (or the chunk start/end).
5. If fewer than 50% of words matched, discard everything and return `estimateTimings(words, durationMs)` with `timingSource: 'estimated'`. Otherwise return `timingSource: 'engine'`.
6. Clamp so that `0 ≤ s(i) ≤ e(i) ≤ D` and `s(i+1) ≥ s(i)`.

**(c) Active word lookup** — `findActiveWord(timings, tMs)`: the last word with `s ≤ t`, by binary search. `t` before the first start returns 0. `t` after the last end returns the last index. With the golden timings above: `t = 400 → 0`, `t = 467 → 1`, `t = -5 → 0`, `t = 9999 → 1`.

**(d) Highlight clock.** `t = sink.current().positionMs + lookaheadMs`. `lookaheadMs` is a per-platform constant (default 0 on web and desktop, 80 on Android) held in settings. The UI samples on `requestAnimationFrame` (DOM) or at most every 50 ms (Android).

**(e) Speed plan** — `planSpeed(rate, sinkMaxRate)`. User rates are 0.5–5.0 in steps of 0.05.

```
synthSpeed    = clamp(ceilToQuarter(rate / sinkMaxRate), 1.0, 4.0)
sinkRate      = min(sinkMaxRate, rate / synthSpeed)
effectiveRate = synthSpeed · sinkRate
```

`ceilToQuarter(x)` rounds up to the next multiple of 0.25. Normally `synthSpeed = 1.0`, so one cached chunk serves every speed. Golden: `(1.5, 16) → {1.0, 1.5, 1.5}`, `(4.5, 2) → {2.25, 2.0, 4.5}`, `(5.0, 2) → {2.5, 2.0, 5.0}`, `(3.0, 2) → {1.5, 2.0, 3.0}`, `(5.0, 1) → {4.0, 1.0, 4.0}`.

**(f) Progress.** `fraction = (wordsBefore(sentenceIndex) + wordIndex) / wordCount`. Remaining time at rate `r` = `remainingWords / (baseWpm · r)` minutes, where `baseWpm` is a running average of `60000 · words / durationMs` over chunks played with the current voice (initial value 170).

### 5.7 Player protocol and state machine

```ts
type PlayerState = 'idle' | 'loading' | 'ready' | 'buffering' | 'playing' | 'paused' | 'ended' | 'error';

type PlayerCommand =
  | { type: 'load'; docId: string; position?: Position }
  | { type: 'play' } | { type: 'pause' } | { type: 'toggle' } | { type: 'stop' }
  | { type: 'seek'; sentenceIndex: number; wordIndex?: number }
  | { type: 'skip'; sentences: number }            // negative = back
  | { type: 'setRate'; rate: number }
  | { type: 'setVoice'; voiceId: string }
  | { type: 'setSleep'; minutes: number | null };

interface PlayerSnapshot {
  state: PlayerState; docId: string | null;
  sentenceIndex: number; wordIndex: number;
  rate: number; voiceId: string | null;
  sleepRemainingMs: number | null;
  error: { code: string; message: string } | null;
}
```

| From | Event | To | Action |
|---|---|---|---|
| idle | `load` | loading | resolve document, set position |
| loading | document resolved | ready | — |
| ready, paused, ended | `play` | buffering | request current chunk + prefetch window |
| buffering | first chunk enqueued | playing | `sink.play()` |
| playing | `pause` | paused | `sink.pause()` |
| playing | sink `chunk-end` | playing | advance sentence, top up queue |
| playing | sink `queue-empty` with chunks pending | buffering | wait for next chunk |
| playing | last sentence ended | ended | position stays at last sentence |
| any but idle | `seek`, `skip`, `setVoice` | buffering or paused | `sink.clear()`, reposition, refill; resume only if it was playing |
| any | `setRate` | same | recompute `planSpeed`; if `synthSpeed` changed, clear and refill |
| any | chunk or sink failure | error | keep position; `play` retries |
| any | `stop` | idle | `sink.clear()` |

Rules: the prefetch window is the current sentence plus the next 3 non-skipped sentences. Sentences in `skip` blocks are passed over when `skipFurniture` is on. The sleep timer stops playback at the first sentence boundary after it expires. `PlayerController` is pure TypeScript with an injected clock; it never touches DOM or native APIs.

## 6. TTS — `packages/core-tts`

```ts
interface Voice { id: string;            // 'kokoro:af_heart'
                  engine: string; engineVoiceId: string; name: string; lang: string }
interface TtsEngine {
  id: string;                            // 'kokoro' | 'piper' | 'mock'
  listVoices(): Promise<Voice[]>;
  synthesize(req: { text: string; engineVoiceId: string; synthSpeed: number }):
    Promise<{ audio: Uint8Array; mime: 'audio/mpeg' | 'audio/wav'; durationMs: number;
              engineTokens: { text: string; s: number; e: number }[] | null }>;
}
```

- `chunkId = sha256Hex([engine, engineVoiceId, synthSpeed.toFixed(2), text].join('\u0000')).slice(0, 40)`.
  Golden: `['mock','mock-a','1.00','Hello, world.']` → `3bfbfd2ad841c9c08af4bcc1c7ccb8560d318c76`; `['kokoro','af_heart','1.00','Hello, world.']` → `de77348a49abbad5c340cede3e9a7fdda8c05403`.
- **Kokoro adapter:** `POST {KOKORO_URL}/dev/captioned_speech` with `{ model: 'kokoro', input, voice, speed, response_format: 'mp3', stream: false }`. The JSON response has `audio` (base64) and `timestamps` (`[{ word, start_time, end_time }]`, seconds). Voices come from `GET /v1/audio/voices`. Engine speed is accepted in 0.25–4.0. Word timestamps exist only for languages Kokoro supports them in; an empty array means estimated timings.
- **Piper adapter:** `POST {PIPER_URL}/synthesize` with `{ text, voice, length_scale: 1 / synthSpeed }` returns WAV. Duration is computed from the WAV header. `engineTokens` is `null`. Voices come from `GET /voices`.
- **Mock adapter:** returns a valid 16-bit mono 22 050 Hz WAV of a 220 Hz tone lasting `60 ms × alnum characters`, minimum 200 ms, divided by `synthSpeed`. `engineTokens` are derived with `estimateTimings`, so the alignment path is exercised. Voices: `mock:mock-a`, `mock:mock-b`.
- The hub runs the tokenizer on the chunk text and aligns engine tokens (F§5.6b), so the client receives ready `WordTiming[]`.

## 8. Library and sync

### 8.1 Model

The hub is the meeting point, not the owner. Each device keeps a full local library and an outbox of `Op`s (F§5.9). Audio is not synced; any device can re-request a chunk from the hub's shared TTS cache.

### 8.2 Push and pull

- **Push:** the client sends up to 200 pending ops. For each op the hub ignores it if `opId` was seen (idempotent), applies the LWW rule against the stored record, and — when the op wins — stores the record and appends a row to `changes` with a new autoincrement `rev`. Every op in the request is returned in `accepted`, including ops that lost LWW.
- **Pull:** the client asks for changes with `rev > since` (limit 500), applies them with `applyRemote`, then stores `nextRev` as its cursor. Changes originating from the same `deviceId` are still returned and are no-ops under LWW.
- **Document bodies:** before pushing a `document` put, the client uploads the model with `PUT …/model`. A client that pulls a `document` change it has no model for downloads it lazily when the document is opened, or eagerly when on Wi-Fi/desktop.
- **Order of a sync round:** upload models → push → pull → repeat pull while `more` is true.

### 8.3 WebSocket change feed

The client opens `GET /v1/sync/ws` and sends `{ "type": "auth", "token": "…" }` as its first message within 5 seconds. The hub replies `{ "type": "ready", "rev": n }` or closes with code 4401. After that the hub sends `{ "type": "changed", "rev": n }` whenever `rev` increases, and `{ "type": "ping" }` every 30 seconds; the client answers `{ "type": "pong" }`. The feed carries no data. A `changed` message triggers a pull. Clients reconnect with exponential backoff from 1 s to 60 s and also pull on app foreground and every 5 minutes.

### 8.4 Hub tables

`records(entity, entity_id, ts, device_id, deleted, json, PRIMARY KEY(entity, entity_id))`, `changes(rev INTEGER PRIMARY KEY AUTOINCREMENT, entity, entity_id)`, `seen_ops(op_id PRIMARY KEY, received_at)`, `summaries(doc_id, mode, model, prompt_version, status, json, updated_at)`, `schema_migrations(version)`. Document models and originals are files under `{DATA_DIR}/library/{docId}/`.

## 9. AI features

```ts
interface LlmProvider {
  complete(req: { system: string; user: string; json: boolean; maxTokens: number }): Promise<string>;
}
```

- One adapter, `OpenAiCompatibleProvider`: `POST {LLM_BASE_URL}/chat/completions` with `{ model, messages, max_tokens, response_format: { type: 'json_object' } }` when `json` is true.
- **Summarization** is map-reduce. Non-skipped blocks are packed into segments of at most 12 000 characters, never splitting a block. *Map*: each segment → up to 8 bullet notes (JSON `{ notes: string[] }`). *Reduce*: all notes → `{ summary: string, keyTakeaways: string[] }`. `mode: 'brief'` asks for ≤ 120 words and 5 takeaways; `mode: 'detailed'` asks for ≤ 400 words and 8–10 takeaways. A single-segment document skips the map step.
- Every model reply is parsed with zod. On a parse failure the hub retries up to 2 times with the validation error appended. A third failure sets `status: 'error'`. The validation schema is deliberately looser than the prompt (brief: ≤ 1 200 characters and 3–6 takeaways; detailed: ≤ 4 000 characters and 6–12), so a small overshoot does not fail a job.
- Results are cached by `(docId, mode, LLM_MODEL, promptVersion)`. Jobs run one at a time in-process; state lives in the `summaries` table, so a restart turns `running` rows into `error` with code `INTERRUPTED`.
- **Listen to the summary:** the client builds a `DocumentModel` with `source.kind = 'summary'` from the summary and takeaways using `buildDocument`, and plays it through the normal player.
- Prompts are original and live in `apps/server/src/ai/prompts.ts` with a `PROMPT_VERSION` constant.

## 10. Platform capabilities

### 10.1 Web app — `apps/web`

- Hash-routed SPA: `#/library`, `#/read/:docId` (`?autoplay=1` starts playback after load), `#/import` (`?url=` imports a link), `#/settings`, `#/mini`.
- Import by file picker, drag-and-drop, pasted text, or URL; all go through `POST /v1/parse`.
- Reader: reflowed text (`ReaderView`) with sentence and word highlights (CSS Custom Highlight API), click-to-seek, auto-scroll that pauses for 4 s after manual scrolling.
- PDF page view: `pdfjs-dist` canvas + text layer; highlights are positioned from `PdfAnchor`s, which is exact because hub and client use the same `pdfjs-dist` version and item order.
- Player bar: play/pause, ±1 sentence, speed 0.5×–5.0× (slider plus presets 1, 1.5, 2, 3, 4.5), voice picker, sleep timer, progress and time remaining.
- Keyboard: `Space` toggle, `←`/`→` sentence skip, `[`/`]` speed ∓0.1, `Esc` close panels.

- Offline: a service worker precaches the app shell; "Download for offline" synthesizes every sentence of a document into the `BlobCache` and pins it against eviction.

### 10.2 Chrome extension — `apps/extension`

| Context | Responsibility |
|---|---|
| Background service worker | Message router, context menu ("Read selection", "Read from here"), `commands` shortcuts, creates the offscreen document, tracks the active reading tab. |

- Loaded unpacked; not published to any store.

### 10.4 Android — `apps/android`

- Expo app with `"platforms": ["android"]`. No `ios` directory, no iOS keys in app config, no iOS-only packages. Native project files come from `expo prebuild --platform android` and are not committed or hand-edited.

- Verified on an emulator or device with `adb`: on-device conformance, media session state, lock-screen transport commands, share intents, offline playback.

## 11. Security and privacy

- One bearer token. No user table, no sign-up, no password reset, no OAuth.
- The hub is meant to be reached over a private network (VPN) or behind the operator's own TLS reverse proxy. It ships no TLS of its own.
- Documents, audio, and summaries never leave the operator's machines, except to the LLM endpoint the operator configures.
- No analytics, crash reporting, or update pings in any client.
- Electron: context isolation, sandbox, no remote module, navigation restricted to the app's own files, external links open in the system browser.
- Android: cleartext HTTP is allowed because the hub is reached over a private network; the token is kept in the platform secure store.
- Extension: no remote code, no `eval`, hub origin only.
