## 3. Architecture notes

### 3.1 The bar as designed (F§10.1, F§5.7)

The bar is one presentational surface with two variants. `full` is a column: a progress strip across the whole
width, then one row of controls, then the error line when there is one. `compact` is the same row without the
three panels, which is what F§10.1's mini-player needs.

The row, left to right: **transport** (previous sentence, play/pause, next sentence), then the **speed**
control, the **voice** picker and the **sleep timer**, then the **clock** — a spinner while the audio is being
fetched and the time remaining — pushed to the trailing edge.

Each group is a `<fieldset aria-label="…">`, which is what gives it role `group` and an accessible name
(Biome's `useSemanticElements` rejects `role="group"` on a `div`). Inside a group:

| Group | Controls | What the reader sees |
|---|---|---|
| Transport | three buttons, 36 × 36 px targets | a triangle, two bars or a triangle, the same triangle mirrored |
| Speed | a range input over `RATE_MIN`–`RATE_MAX` in `RATE_STEP` steps, five preset buttons (`RATE_PRESETS`), a gauge icon | the multiplier, the words per minute, and the preset as a pressed button |
| Voice | a filter input, one group per language then engine, one button per voice | the voice's own name, the selected one pressed |
| Sleep timer | four length buttons plus Off, a clock icon | the countdown in minutes while it runs, "Off" otherwise |
| Clock | a spinner (`role="status"`) and the time remaining | the spinner only in `loading`/`buffering` |

Every control is a native `<button>`, `<input type="range">` or `<input type="search">`, so keyboard operation
and focus order come from the platform and no control needs a key handler. Each one carries its own accessible
name (a label, or `aria-label` where the control is an icon); the glyphs themselves are `aria-hidden="true"`.

**Command mapping.** The bar holds no playback state. Every field it draws comes from the `PlayerSnapshot`
prop, and every user action leaves as a `PlayerCommand`:

| Reader action | Command |
|---|---|
| play button while `state` is not `playing` | `{ type: "play" }` |
| the same button while `playing` | `{ type: "pause" }` |
| previous / next sentence | `{ type: "skip", sentences: -1 }` / `{ …, sentences: 1 }` |
| a preset, or the slider | `{ type: "setRate", rate }` (clamped to `RATE_MAX`) |
| a voice row | `{ type: "setVoice", voiceId }` (F§6's `engine:voice` id) |
| a timer choice | `{ type: "setSleep", minutes }`, `null` for Off |

The only state any component holds is the text in the voice filter box — a view detail, not a playback field.

### 3.2 Measured facts that shaped the code

1. **vitest loads the environment with a bare `import('happy-dom')` from its own chunk.** `vitest@5.1.0`
   `dist/chunks/index.Bi0NXYPf.js:1289` is `const { Window } = await import('happy-dom')`, so the package is
   resolved from *vitest's* real path, not from the project's: a rehearsal tree that borrowed the repository's
   `vitest` binary failed with `Cannot find package 'happy-dom' imported from
   …/node_modules/.pnpm/vitest@5.1.0_vite@8.3.8…/node_modules/vitest/dist/chunks/index.Bi0NXYPf.js`
   (`ERR_MODULE_NOT_FOUND`, 2 unhandled errors, "Test Files no tests"). It resolves in the repository only
   because pnpm hoists the package into `node_modules/.pnpm/node_modules`, which is on that chain — measured
   directly: a two-project workspace whose `packages/a` declares `happy-dom` ends with
   `node_modules/.pnpm/node_modules/happy-dom`, while a single root project declaring the same package does not
   (the root's own dependencies are already at the root's `node_modules`, so pnpm does not hoist them).
2. **`@testing-library/react@16.3.3` declares `@testing-library/dom` as a peer, not a dependency** (its
   `dependencies` are `@babel/runtime` alone). pnpm installed `@testing-library/dom@10.4.2` automatically: it is
   in the virtual store and inside RTL's own virtual-store `node_modules`, which is how `render`, `screen` and
   `fireEvent` resolve. Nothing in this unit declares it.
3. **Biome's recommended preset errors on `role="group"` over a `div`.** The first read-only rehearsal reported
   `lint/a11y/useSemanticElements` five times ("The elements with this role can be changed to the following
   elements: `<fieldset>`"), plus one `format` (a hand-wrapped `<button>` that fits inside 140 columns) and
   three `assist/source/organizeImports` — the inline `type` modifier sorts *with* the names
   (`{ clampRate, type PlayerCommand, RATE_MAX, … }`), an `import type … from "@lectern/core"` line sorts
   before the value import from the same specifier, and in the barrel `./components/icons` sorts before
   `./components/PlayerBar`. All nine were fixed on this unit's own files (`biome check --write`), never on a
   frozen file, and the chain was re-run afterwards because the write edits the files the run proves.
4. **The typecheck program is exactly the unit's seven non-test modules** — `src/format.ts`,
   `src/components/{icons,SleepTimerMenu,SpeedControl,VoicePicker,PlayerBar}.tsx`, `src/index.ts` — and the
   second program (`include: ["src"]`, `exclude: []`, the delivered test files included) reports **zero**
   diagnostics. This package's tests import no `node:` module, so unlike the fixture-reading and stub-serving
   test files of U-006/U-016/U-017 the delivered tests need no exclusion and the contract needs no operator
   patch. `tsconfig.json` narrows the program to `src` and excludes `src/**/__tests__` so `vitest.config.ts`
   (which imports `vitest/config`, and through it `vite`) is not compiled.
5. **`happy-dom@21.0.4` declares no `exports` map** (a bare specifier resolves by `main`) and its own
   `dependencies` are `@types/node >= 20.0.0`, `@types/whatwg-mimetype`, `@types/ws`, `entities`,
   `whatwg-mimetype`, `buffer-image-size` and `ws`. So installing it puts `@types+node` in the pnpm virtual
   store transitively — nothing this unit declares, and not reachable from any package's default `typeRoots`
   (`<pkg>/node_modules/@types`, `<repo>/node_modules/@types`), which is why the ui-web program's file list
   contains `lib.dom.d.ts` and `@types/react` and no `@types/node`.
6. **The renderer needs no bundler configuration beyond the plugin.** With `jsx: "react-jsx"` in the package
   tsconfig and `@vitejs/plugin-react` in `vitest.config.ts`, `.tsx` test files and `.tsx` sources both

   repository's `vite@8.3.8`) and marks its three other peers — `oxc-transform-react`,
   `@rolldown/plugin-babel`, `babel-plugin-react-compiler` — optional, so no undeclared package arrives.

## 4. Lectern design

- [DESIGN] **The arrangement is Lectern's own.** F§10.1 fixes the controls and their range, not their order or
  their sizes: the bar is pinned along the bottom edge, full width, with the progress strip above one row;
  transport first, the three panels in the middle, the clock at the trailing edge. The reference product's
  arrangement was not observed (inspection UNAVAILABLE), so nothing here is a parity claim.
- [DESIGN] **The three panels are rendered inline, not behind popovers.** That removes disclosure state from
  every component, so the only component-local state in the package is the voice filter string and every
  playback field comes from the snapshot (the contract's *Forbidden Actions*).
- [DESIGN] `formatRate` writes at most two decimals and drops trailing zeros: `1 → "1×"`, `1.5 → "1.5×"`,
  `4.5 → "4.5×"`, `1.25 → "1.25×"`. The contract fixes the `1.5` case only.
- [DESIGN] `formatRemaining` reports whole minutes and **rounds up**, because a countdown reading "1 min" with
  90 seconds left is closer to the truth than "2 min"; `0` and negatives are `"0 min"`. The contract fixes the
  `720000 → "12 min"` case only.
- [DESIGN] `formatWpm(rate, baseWpm)` is `round(rate × baseWpm)` and `" wpm"`. F§5.6(f) seeds `baseWpm` at 170
  and the contract fixes the signature, not the rounding.
- [DESIGN] **The slider clamps before it speaks**: the change handler passes the input's value through core's
  `clampRate`, so no drag or keystroke can emit a rate above `RATE_MAX`; the same control publishes
  `aria-valuetext` as `"1.5×, 255 wpm"` so the multiplier and the pace are readable from the slider itself.
- [DESIGN] **Icons are inline SVG from basic shapes** (polygons, rectangles, circles, arcs) on one 24-unit
  viewBox, `aria-hidden="true"` and `focusable="false"`, inheriting `currentColor` and the control's size. The
  contract lists nine glyphs and all nine ship; `close` and `bookmark` have no control in this unit yet and are
  there for the units that own those actions.
- [DESIGN] **The theme is a token set.** `:root` declares `--lectern-ink`, `--lectern-paper`, `--lectern-accent`,
  `--lectern-sentence`, `--lectern-word`, a muted ink, a surface, a line, a danger colour, five spacing steps
  and three radii; the dark theme overrides the colours, follows `prefers-color-scheme` and can be pinned with
  `data-lectern-theme` on the root element. Type is the platform's system stack (no web font), and the spinner's
  animation has a `prefers-reduced-motion` branch.
- [DESIGN] `compact` keeps the transport, the rate and the pace and the clock, and drops the three panels — the
  mini-player of F§10.1.
