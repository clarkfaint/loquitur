## 3. Architecture notes

**The feed carries no data (F§8.3).** A `changed` message is a nudge, not a payload: it tells a client that
`rev` moved, and the client answers it with an ordinary pull over U-056's HTTP routes. The server's whole
message set is `ready` with a `rev`, `changed` with a `rev`, and a periodic `ping`; no record, document text
or token ever crosses the socket. That is what makes the socket cheap to hold open and safe to expose.

**Authentication is the first message, never the address.** A socket has no header to carry F§11's bearer
token, and F§8.3 forbids the token in the URL, a cookie or a subprotocol header. So the client's first
message must be `{ "type": "auth", "token": "…" }`, and the comparison is `constantTimeEquals` — the same
constant-time comparison U-019's HTTP hook uses — so a guess cannot be read off the timing. Every failure
closes the socket with **4401**: a wrong token, a first message that is not an authentication, a frame that is
not JSON, or silence past `wsAuthTimeoutMs` (5 s by default).

**`ready` and the subscription are one step.** The feed takes `records.onChange(...)` and reads
`records.currentRev()` synchronously, then sends `ready` with that rev. No commit can slip between the
subscription and the message, so a client that starts pulling from the rev it was handed cannot miss a change
that happened while the socket was authenticating.

**A socket that stops answering is closed.** The feed pings every `wsPingIntervalMs` (30 s by default); a
`pong` clears both the outstanding ping and the miss count. A ping that was not answered is counted at the
next tick, and the **second** unanswered ping closes the socket — F§8.3's "close after two unanswered
pings". F§8.3 names no close code for this case (only `4401` for a failed authentication), so the hub uses
the application code **4408** beside it.

**Every socket closes with the hub.** The plugin closes the server's own clients as the server stops; the
sockets this feed holds are closed in its own `onClose` hook with `1001` and a shutdown reason, so a hub that
shuts down leaves none of them open. A socket's own `close` event clears the auth timer, the ping interval and
the change subscription, so nothing keeps ticking after the client is gone.

**A request without an upgrade is refused, not ignored.** The route is registered with a `wsHandler` beside an
ordinary handler, which is what tells the two kinds of request apart: an upgrade is handed to the feed, and a
plain HTTP `GET` — a probe, a health check, a client that forgot to upgrade — reaches the handler and is
answered `426 Upgrade Required` with F§7.2's envelope and an `upgrade: websocket` header. A client that probed
the path still parses one shape.

**The plugin is registered before the registry runs.** `app.ts` registers `@fastify/websocket` before
`for (const route of routes) route(app, context)`, because the plugin reads the route table as routes are
added: a route declaring a `wsHandler` is a socket route, and every other request to that path stays an
ordinary HTTP request. The plugin takes the server's upgrade path in place of the bare `upgrade` event, so a
socket runs the same request hooks and reaches the route it named.

## 4. Lectern design

- [DESIGN] **The feed is one route module registered through the registry.** `syncWsRoutes(app, ctx)` owns the
  path and nothing else; the plugin's registration stays in `app.ts`, where the route table's order matters.
- [DESIGN] **The socket surface is declared locally, not imported from the plugin's typings.** `FeedSocket`
  names the four members the feed uses (`send`, `close`, `on`, and the event names it listens to), and the
  route options type extends Fastify's `RouteOptions` with `wsHandler`. This is the same boundary U-046 and
  U-055 established for a module whose typings carry `@types/node`: the module is the real one at runtime, and
  the compiler never loads its declarations.
- [DESIGN] **The plugin's default export is reached through a `string`-typed specifier.** `app.ts` holds
  `const WS_PLUGIN_SPECIFIER = "@fastify/websocket" as string;` and imports it dynamically at build time of
  the app, declaring the one member registered as `(instance: FastifyInstance) => Promise<void>`.
- [DESIGN] **`4401` is the authentication failure and timeout code; `4408` is the two-unanswered-pings code.**
  F§8.3 names only `4401`; the second code is the application code beside it, chosen so a client can tell the
  two failures apart.
- [DESIGN] **A `426` names what the client must do.** F§8.3's own test accepts "400 or 426"; the route sends
  `426 Upgrade Required` with `upgrade: websocket`, because the request is well-formed and the only thing
  wrong is that it did not ask to upgrade.
- [DESIGN] **The two feed clocks are configuration, not constants.** `wsAuthTimeoutMs` (default 5000) and
  `wsPingIntervalMs` (default 30000) are added to the strict `ConfigSchema`, read from
  `LECTERN_WS_AUTH_TIMEOUT_MS` and `LECTERN_WS_PING_INTERVAL_MS`, so a test drives the feed's clocks in
  milliseconds instead of waiting out thirty seconds.
- [DESIGN] **The auth hook exempts the feed path for its own reason.** `auth.ts` exports `WS_FEED_PATH` and
  puts it beside `/healthz` in `EXEMPT_PATHS`: a socket cannot carry an `Authorization` header before it is
  upgraded, so the path authenticates with its first message instead. A request that arrives on the path
  without an upgrade is refused by the route itself and reads nothing.
- [DESIGN] **The ping interval starts at authentication, not at connection open.** A socket that has not
  authenticated is on the auth deadline; pinging it would only add noise to a socket that is about to be
  closed.
- [DESIGN] **The feed's message set is built through U-054's own schemas.** Every server message is
  `WsServerMessageSchema.parse(...)`-validated before it is sent, and every client message is
  `WsClientMessageSchema.safeParse(...)`-validated before it is read, so the wire shape is the contract's and
  not a string literal in this module.

## 7. Deviation proposals

1. **`4408` is the close code for two unanswered pings.** F§8.3 names only `4401` for a failed
   authentication and no code for a socket that stops answering. The hub uses the application code beside it
   so a client can tell the two failures apart. A patched contract that wants a specific code can name it;
   the accounting (count at the next tick, close on the second) would not change.
2. **A non-upgrade `GET` is answered `426`, not `400`.** F§8.3's own test accepts "400 or 426"; the request
   is well-formed and only lacks the upgrade, so the route sends `426 Upgrade Required` with an
   `upgrade: websocket` header. A patched contract that prefers `400` can say so.
3. **The plugin's typings are bypassed, and the socket surface is declared locally.** This is U-055's repair
   for a module whose typings carry `@types/node`: the module is the real one at runtime and the compiler
   never loads its declarations. A patched contract could instead accept the 83 `@types/node` files and the
   two frozen `packages/core` errors, or exclude the declarations some other way; neither is writable from
   this unit's *Patch scope*.
4. **Two settings are added to the strict `ConfigSchema`.** F§7.1's table does not name `wsAuthTimeoutMs` or
   `wsPingIntervalMs`, but the contract's *Patch notes* ask for them. They are validated as positive integers
   and default to 5000 and 30000 ms. A patched contract could spell them as fixed constants instead.
5. **The auth exemption is a path in `auth.ts`'s set.** The feed path is exempt from the header check and
   authenticates by first message; a request without an upgrade is refused by the route itself. A patched
   contract could instead have the plugin answer authentication before the hook runs, which would remove the
   exemption but add a plugin-level hook this unit's scope does not name.
6. **The ping clock starts at authentication.** A socket that has not authenticated is on the auth deadline,
   and pinging it would only add noise to a socket that is about to be closed. A patched contract that wants
   pings from connection open can say so.
