## 3. Architecture notes

**Authentication is a first message, never the address (F§8.3, F§11).** A socket has no header to carry the
bearer token before it is upgraded, and the contract forbids the token in the URL, a cookie or a subprotocol
header. The client's first message must therefore be `{ "type": "auth", "token": "…" }`, within
`wsAuthTimeoutMs` (5 s default). The comparison is U-019's constant-time one. Every failure — a wrong token,
a first message that is not an authentication, or silence past the deadline — closes with `4401`, and nothing
is sent first.

**`ready`, then `changed`.** The current `rev` is read and the `onChange` subscription is taken in one
synchronous step, *before* `ready` goes out, so no commit can slip between the two unnoticed. Every commit
that moves `rev` sends `changed` with the new value. The subscription is released when the socket closes.

**The feed carries no data.** A `changed` message carries only the new `rev`; the client answers with an
ordinary HTTP pull. No record, document text or token crosses the socket — the contract's first *Forbidden
Action*.

**`ping`, and a silent socket is closed.** A `ping` goes out every `wsPingIntervalMs` (30 s default). The
clock counts an *unanswered* previous ping before sending the next one, so the second unanswered ping closes
the socket; a `pong` clears both the count and the outstanding flag.

**Every socket closes with the hub.** The route's own `onClose` hook closes the sockets it holds with `1001`
and a shutdown reason, so a hub that stops leaves none open.

**A request without an upgrade is not a socket.** The route registers an ordinary `handler` beside the
plugin's `wsHandler`, so a plain `GET` on the path is answered `426 Upgrade Required` with an
`upgrade: websocket` header through F§7.2's envelope.

## 4. Lectern design

- [DESIGN] **The plugin is reached through a `string`-typed specifier, its one used member declared locally.**
  `const WS_PLUGIN_SPECIFIER = "@fastify/websocket" as string;` with
  `type WebSocketPlugin = (instance: FastifyInstance) => Promise<void>;`, then
  `const { default: websocket } = (await import(WS_PLUGIN_SPECIFIER)) as { default: WebSocketPlugin };` and
  `await app.register(websocket);` — the repair this repository already uses for a contract-named package
  whose typings carry `@types/node` (U-046's addon, U-055's `better-sqlite3`). The module registered at
  runtime is the real plugin; the declarations never enter the program (§2).
- [DESIGN] **The plugin is registered before the route registry runs**, in `buildApp`, because it reads the
  route table as routes are added: a route declaring a `wsHandler` becomes a socket route. Registering it
  after the registry would leave the upgrade undispatched.
- [DESIGN] **`/v1/sync/ws` is exempted from the header check and the path is named once.** `auth.ts` gains
  `export const WS_FEED_PATH = "/v1/sync/ws";` and `EXEMPT_PATHS = new Set([HEALTH_PATH, WS_FEED_PATH])`; the
  route module imports the same constant, so the hook and the route cannot drift. The deviation is documented
  in the source: a socket cannot carry an `Authorization` header before it is upgraded.
- [DESIGN] **The feed's two intervals are configuration.** `config.ts` gains `DEFAULT_WS_AUTH_TIMEOUT_MS =
  5000` and `DEFAULT_WS_PING_INTERVAL_MS = 30000`, two `z.int().min(1)` fields on the strict
  `ConfigSchema`, and two `asInteger` reads for `LECTERN_WS_AUTH_TIMEOUT_MS` and
  `LECTERN_WS_PING_INTERVAL_MS`, so a test can drive the feed's clocks in milliseconds.
- [DESIGN] **A socket's surface is declared locally.** `interface FeedSocket { send; close; on }` and
  `type FeedRouteOptions = RouteOptions & { wsHandler: (socket: FeedSocket) => void }` — the whole surface
  the feed touches, so the compiler never loads the plugin's declarations (§2). The plugin hands one of its
  own sockets to `wsHandler`, so the object at runtime is the real thing.
- [DESIGN] **The credential is read beside the parsed envelope.** `WsClientMessageSchema` pins the `auth`
  discriminator and names no token, so the message is validated by that schema and the string it carried is
  read from the accepted value (`tokenOf`), keeping F§11's "the token is opaque" true.
- [DESIGN] **A non-text frame fails authentication.** `ws` hands a message over as bytes; a frame that is not
  text reads as the empty string, which no F§8.3 message parses as, so it fails rather than being answered.
- [DESIGN] **The close code for a silent socket is `4408`.** F§8.3 names `4401` for a failed authentication and
  no code for missed pings, so the hub uses the application code beside it and records it as a deviation (§7).
- [DESIGN] **The feed's tests speak the wire.** `inject` cannot carry a socket, so the suite builds the real
  hub, listens on an ephemeral port and drives Node's built-in `WebSocket` client, with the two clocks taken
  from the environment per case (200 ms auth deadline, 20 ms ping interval).

## 7. Deviation proposals

1. **The close code for a socket that stopped answering pings is `4408`.** F§8.3 names `4401` for a failed
   authentication and no code for the missed-ping case, while the contract's third *Forbidden Action*
   requires the socket be closed. A patched contract could name the code, or require `1000`.
2. **A plain `GET` on the path is answered `426 Upgrade Required`, not `400`.** The contract's own test
   permits either; 426 with `upgrade: websocket` names what the client must do.
3. **"Two unanswered pings" is counted before the next ping is sent**, so a silent socket closes on the
   second interval. A patched contract could instead let two full intervals elapse first.
4. **The two intervals' environment names are `LECTERN_WS_AUTH_TIMEOUT_MS` and `LECTERN_WS_PING_INTERVAL_MS`.**
   The contract names the settings and defaults but not the variables; these follow F§7.1's
   `LECTERN_`-prefixed convention.
5. **The plugin is reached through a `string`-typed dynamic import** (§4), because a static import re-breaks
   the two frozen `packages/core` parser lines and no writable file may exclude the declarations. A patched
   contract could widen *Patch scope* to `apps/server/tsconfig.json` instead.
6. **`pnpm --filter @lectern/server run build` names a script this package does not have** (§2, §6.1). The
   bundle is `apps/server/build.mjs`; a patched contract could add a `build` script to the manifest or name
   that script in the contract.
