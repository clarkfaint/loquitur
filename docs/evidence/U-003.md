## 3. Architecture notes

**The sentence scan (F§5.3), as a state machine over one block's text.** The scanner walks the text once
with a single cursor and no backtracking. At each character it does nothing until a *terminator*
(`.`, `!`, `?`, `…`) appears; that character begins a terminator **run** of one or more terminators, the
run is followed by any number of *closers* (`"`, `'`, `)`, `]`, `”`, `’`, `»`), and a boundary is only a
**candidate** when at least one whitespace character follows the closers *and* the first non-whitespace
character after them is an uppercase letter, a digit, or an opener (`"`, `'`, `(`, `[`, `“`, `‘`, `«`).
The cursor then resumes *after the terminator run*, not after the closers, so a closer can never be
mistaken for a new terminator.

A candidate becomes a boundary unless it is **rejected**, and rejection is the interesting half. Only a
run that is exactly one `.` can be rejected, and the deciding fact is the token immediately before it —
the maximal run of letters and inner dots that ends where the `.` begins. Three rules reject it:
the token lower-cased is in the case-insensitive set (`dr`, `u.s`, `jan`, `e.g`, `i.e`, …); the token
*as spelled* is in the exact-case set (`Art`, `Cal`, `App`, `Id`, `St`, …); or the token is a single
letter (the `v.` of a case name, the `J.` of an initial). Two things about that token are load-bearing
and easy to get wrong: it extends over **inner dots**, which is the only way `e.g.` and `U.S.` are
recognised as one token rather than as a trailing letter, and the exact-case set exists precisely so a
lower-case ordinary word is not mistaken for a citation abbreviation — `Open the app.` splits while
`Cal. App. 4th` does not.

Each golden case pins one arm of that machine: case 1 pins `dr`/`jan` (case-insensitive rejection) and
the fact that the dot of `3.15` and of `p.m.` is never a candidate in the first place (a digit follows,
not whitespace); case 2 pins `v` (single letter), `u.s` (inner dots, case-insensitive) and — negatively
— `id.`, which is *not* rejected at all but is saved by its follower `at` being lower-case, so the
case-insensitive/exact-case split is what makes `Id.` matter only when capitalised; case 3 pins the run
of three dots (`Wait...` is followed by a lower-case `w`, so it is not a candidate) and the `?`;
case 4 pins the closer: the boundary after `"Stop."` includes the closing quote inside the sentence;
case 5 pins initial-rejection twice in one block; case 6 pins the exact-case set's whole purpose —
`app.` splits, `Art.` does not.

**Where sentence ranges stop.** The end of the block always ends a sentence, whether or not a candidate
was found there, and every range is trimmed, so ranges are disjoint, non-empty, and separated by the
whitespace they exclude. A range therefore never contains its leading or trailing whitespace, and the
only characters of a block that no sentence covers are whitespace characters. A block that is empty or
whitespace-only produces no ranges at all.

**The 400-character split.** A range longer than 400 characters is broken repeatedly: the break is the
last `,`, `;`, `:` or `—` inside the piece's first 400 characters, and the piece keeps that punctuation;
failing that, the break is the last space in the same window; failing that — a 400-character run of
letters with no space and no punctuation — the piece is cut at exactly 400 characters, because a rule
with no break point at all would not terminate. The remainder is re-trimmed and re-tested, so the rule
is applied to the head of what is left rather than to the original range; each piece is consequently
never longer than 400 characters, which is the property the contract's own test sentence states.

**Words.** A word is a maximal run of non-whitespace characters, with one repair: a run that contains no
letter and no digit (a lone dash, an ellipsis, a bullet) is *not* a word, and is merged into the range of
the word on its left — extending that word's range to the run's end, which necessarily also spans the
whitespace between them — or into the word on its right when it comes first. Merging right rather than
dropping the run is what keeps the coverage invariant true: every non-whitespace character of the block
lies in exactly one word, so a dash has to live in *some* word's range, and the sentence highlight and
the word highlight then agree about which characters they span. `Word.text` is `Sentence.text.slice`
of the range, never a reconstruction, and the range is relative to `Sentence.text` — while
`Sentence.charStart`/`charEnd` are relative to `Block.text`, which is what makes both invariants
checkable in one expression each.

**Indices.** `splitSentences` returns plain ranges, because a range does not know which document it is
in. `tokenizeBlock` is the composition that knows: it turns each range into a `Sentence` with a **global**
`index` (the block's first sentence index plus the offset within the block), the owning `blockIndex`, and
the words of the sentence, and it is the only function of the three that touches the F§5.1 model.

## 4. Lectern design

- [DESIGN] The scanner works on the block text as given and never rewrites it: ranges are offsets into the same string, and a range's text is `text.slice(charStart, charEnd)`. The contract's *Forbidden Actions* forbid trimming or altering characters inside a range, and slicing is the only construction that cannot — follows the contract and F§5.1 (`Sentence.charStart`/`charEnd` are *"offsets into Block.text"*).
- [DESIGN] The abbreviation sets are the two `Set`s of F§5.3 verbatim, one case-insensitive (compared through `token.toLowerCase()`) and one exact-case (compared as spelled), each exported as `ReadonlySet<string>` so no caller can add to them at run time. F§5.3 fixes the members and the contract forbids changing them; the two-set split *is* the rule, not a convenience — `Id.` suppresses a boundary while `id.` does not, and `App.`/`Cal.` behave the other way round from `app.`/`cal.` — follows F§5.3.
- [DESIGN] Character classification is by `String.prototype.charAt(pos)`, not by `text[pos]`. Measured in section 2: `noUncheckedIndexedAccess` makes the indexed read `string | undefined`, which would force a fallback or a cast into every one of the scanner's comparisons; `charAt` is typed `string` and returns `""` past the end, which the comparisons already treat as "not a terminator, not whitespace". No cast, no non-null assertion, no `any` — follows AGENTS.md §7 and the measurement.
- [DESIGN] Letters, uppercase letters and digits are matched with `u`-flagged Unicode property escapes (`\p{L}`, `\p{Lu}`, `\p{N}`) rather than with ASCII ranges, so a block of non-Latin text splits on its own terminators and a capitalised non-Latin word starts a sentence. Still no locale data, no `Intl.Segmenter`, no lookbehind, no package — follows the contract's *Forbidden Actions*.
- [DESIGN] The `…` character is a terminator, and closers and openers are the three quote styles each (straight, curly, guillemet) plus `)`/`]` for closers. The sets are exactly the characters F§5.3 lists, written as code-point literals rather than as a single character class, so that a source file's encoding cannot silently change which characters count — follows F§5.3.
- [DESIGN] The 400-character break is searched in a **400-character window** (the piece's first 400 characters), so a punctuation break yields a piece of at most 400 characters including the punctuation. Reading "at or before character 400" as *index ≤ 400* would allow a 401-character piece, which contradicts the property F§5.3's own sentence states; the window reading satisfies both — follows F§5.3.
- [DESIGN] A 400-character window with no `,`, `;`, `:`, `—` and no space is cut at exactly 400 characters. F§5.3 names two breaks and neither exists in such a run; a deterministic hard cut keeps the "at most 400 characters" guarantee and terminates, and an unbreakable run of 400 letters has no defensible break point to prefer — proposal in section 7.
- [DESIGN] `splitSentences` returns a named `SentenceRange` (`{ charStart, charEnd, text }`) — the shape the contract's signature lists — and `Sentence.index` is assigned only in `tokenizeBlock(firstSentenceIndex, blockIndex)`, which is where the global index and the owning block first exist. Splitting the pure-text function from the index-assigning one keeps `splitSentences` and `splitWords` free of the document model, which is what makes the golden cases testable without constructing a document — follows the contract's signatures.
- [DESIGN] A punctuation-only run with no word on either side of it (a sentence of nothing but `—`) becomes a one-word sentence rather than no word at all, so the coverage invariant holds for every input; a merge "into the following word" with no following word has no other defined outcome — follows F§5.3's word rule and the contract's coverage requirement.
- [DESIGN] `TOKENIZER_VERSION = 1` is a module constant, not a schema field: F§5.1 already pins `DocumentModel.tokenizerVersion` to the literal `1`, and the constant exists so the code that must agree with that literal has one place to point at — follows F§5.1.
- [DESIGN] `src/index.ts` gains two export lines for `abbreviations.ts` and `tokenizer.ts`. Both files are this unit's outputs and §5 declares the barrel append-only, so the environment's public entry must reach them — follows AGENTS.md §5.

  `String.prototype.toLowerCase(): string`, `RegExp.prototype.test(string): boolean` — which are standard
  library, not package API. TypeScript 7.0.2 bundles its standard library **inside the executable**: there is

  The signatures could therefore not be quoted from an installed file; the two that matter were pinned by

## 7. Deviation proposals

- [DESIGN → contract] F§5.3 fixes *two* break characters for a long sentence (a `,`, `;`, `:` or `—`;
  otherwise a space) and gives no rule for a run that has neither inside 400 characters. This unit cuts
  at exactly 400 characters, which preserves the "at most 400 characters" guarantee and terminates.
  Proposal: state the hard-cut fallback in F§5.3, or name the maximum a piece may reach when the break
  is a punctuation character.
- [DESIGN → contract] The contract's inspection asks whether the reference reader draws one highlight
  level or two, which no tokenizer can observe and which no unit's evidence can carry: this unit never
  renders anything. F§5.1 gives `Word.text` as *"includes attached punctuation"* and `Position` a
  `wordIndex`, which is *consistent with* a second, word-level highlight, but consistency is not
  evidence. Proposal: let the unit that owns highlighting (the player or the web reader surface) own
  this question, and drop it from U-003's *Questions*.
- [DESIGN → contract] The contract forbids changing the abbreviation sets or the golden cases even if
  the reference product splits differently, which is the right call for a clean-room build but leaves
  the parity question unanswerable in this session (no `T-WEB`, no browser tools). The F§5.3 *known
  limit* — an abbreviation that truly ends a sentence does not split — is the visible cost of that
  choice, and it is accepted there. No change proposed; recorded because the conflict cannot be
  observed, only noted.
