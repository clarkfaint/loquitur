## 3. Architecture notes

**What an import is (F§10.4, F§7.2).** One pipeline with four doors, one dispatcher and one de-duplication rule. A
picked file's bytes, an address, or a block of text is read by the hub at `POST /v1/parse`, and what comes back —
F§5.1's `DocumentModel`, plus the `PdfAnchor`s a paged source produced — is what the library keeps. The one
exception is plain text a reader typed or pasted: F§10.4 says it is built locally with `buildDocument`, so pasted
text works with the hub unreachable, and it never touches the network at all. Nothing on the device parses PDF,
EPUB, DOCX, HTML or an image: a second implementation of F§5.4 in the app would be a second answer to "what is this
document", and the OCR engine belongs where the hub can cache it.

**Identity and duplicates (F§5.2, F§5.9).** A document's identity is `docId`, a hash of its normalized block texts,
so importing the same bytes twice is not a second library entry: the second import answers `{ docId, duplicate:
true }` and writes nothing. The check is `getDocumentMeta(docId) !== null` before any write, which the store answers
`null` for a document whose record is a tombstone — so a document the reader deleted can be imported again, which is
the behaviour the web app's own import already has.

**Classifying a pasted string (contract).** The rule is exactly the contract's: a single `http(s)` URL with no other
text is a URL, and everything else is text. Implemented as "the whole trimmed value contains no whitespace and
parses as a URL whose protocol is `http:` or `https:` and whose host is not empty" — so a URL inside prose is text
(it has spaces), a bare host with no scheme is text (F§7.2's `{ url }` fetches `http:` and `https:` only), and an
empty or whitespace-only string is text whose `text` is empty.

**The library screen's arithmetic (F§5.9, F§5.6(f), F§10.1).** The screen is a view of F§5.9's records and nothing
more: it reads the live documents, the live folders and each document's progress, and draws the list the reader's
search, folder chip and sort ask for — through `@lectern/core`'s own library model (`buildFolderTree`,
`filterDocuments`, `sortDocuments`), which is the same code the web app's library draws itself with, so the two
platforms cannot sort or filter the same records differently. A row's percentage is `documentProgress(meta,
progress)`, which is exact at a document's start and end and within one sentence in between; a row's length is the
`wordCount` the metadata carries, so drawing a library never loads a document's model.

**What the two screens are.** `app/(tabs)/library.tsx` is a header row (search, the three sort chips), a wrapping
row of folder chips (All, No folder, then the tree in name order, each level indented by one step), the document
rows, and an import button; a long press on a row opens a sheet with the two actions the contract names, Move and
Delete. `app/import.tsx` is three ways in — Choose file, Paste, and a text box with its own button — over a list of
the imports this session has run, one row per import, each carrying its own progress, its own error and its own
cancel. Neither screen blocks: every import is an ordinary `await` in a handler, the row paints a spinner while it
is in flight, and the list is redrawn from the store after every action, so a screen never holds a second copy of
the library that a reload would contradict.

## 4. Lectern design

- [DESIGN] **The picker's type list is Lectern's own** (contract, F§5.4): the six formats the hub reads as
  documents — `application/pdf`, `application/epub+zip`, the DOCX type, `text/html`, `text/plain`, `text/markdown`
  — declared once in `import-service.ts` as `SUPPORTED_IMPORT_MIME_TYPES` and handed to the system picker. No
  cloud-drive provider, no account, no built-in browser (contract's first Forbidden Action). Images are deliberately
  not offered here: F§10.4 gives them their own doors — the share sheet and the camera scanner — in later units.
- [DESIGN] **The picker is the system document picker** (`getDocumentAsync`), which is what the contract's third
  Forbidden Action asks for: it returns a URI the app may read for that one file, so the app requests no storage
  permission at all. `copyToCacheDirectory` is left at its default, so the URI the app reads is the app's own cache
  copy rather than a provider URI that may expire.
- [DESIGN] **Text is built on the device, files and addresses are not** (F§10.4, contract's second Forbidden
  Action): `importTextLocal` calls `parseText` → `buildDocument` with no client at all, while `importPickedFile` and
  `importUrl` go through the hub. `importDocumentModel` exists for the doors that already hold a model — a scan, a
  summary — so they do not re-parse text the device produced.
- [DESIGN] **A duplicate is reported, not hidden** (F§5.2): the row says the library already holds that document and
  offers to open it, which is more useful than a silent success and is what makes the de-duplication visible.
- [DESIGN] **Cancel abandons the row, and says so** (contract's fourth Forbidden Action). The hub client takes a
  base URL, a token and a `fetch` and exposes no abort signal, so an in-flight request cannot be stopped from this
  app; the row is therefore removed when the reader cancels, and the screen says plainly that the hub may still
  finish that import and that the document will appear in the library if it does. Claiming an aborted upload would
  be a lie about a request that is still running.
- [DESIGN] **Deleting a document also drops its two blobs** (F§5.9), the original bytes under `orig/<docId>` and a
  paged source's anchors under `anchors/<docId>`, because both are keyed by `docId` and mean nothing once the
  document is a tombstone. The keys are the web app's own, exported from `import-service.ts`, so the two platforms'
  caches stay interchangeable.
- [DESIGN] **A move is an ordinary write** (F§5.9): the document's model travels with the new record, as the web
  app's library does, rather than the folder being patched into a stored row.
- [DESIGN] **Progress is the library's own fraction, not the reader's** (F§5.6(f) through `documentProgress`): a
  list that had to load every document's model to draw a percentage would not be a list.
- [DESIGN] **The library is the first tab** (F§10.4): the tab group's own file order puts `library` before
  `settings`, and the entry route now sends a configured reader to the library and an unconfigured one to Settings —
  which is the contract's Patch note, and the only change this unit makes outside its own files.

## 7. Deviation proposals

None acted on. Three notes for the ledger, none requiring a contract change:

1. **`npx expo install` cannot install into this repository** — the substitution U-045 measured and U-047 repeated:
   its bare `pnpm add` dies on the committed lockfile with `ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION`. The two
   packages this contract names were installed with the spec list `expo@58.0.25`'s own `bundledNativeModules.json`
   resolves them to —
   `pnpm --filter @lectern/android add expo-document-picker@~58.0.5 expo-clipboard@~58.0.4 --config.minimumReleaseAge=0 --config.strictDepBuilds=false`
   — which installed exactly what `expo install` would have (`+2` packages, `Done in 5.1s`), and
   `pnpm-workspace.yaml` survived byte-identical (`sha256 193f4ebeb…`).
2. **The hub client exposes no abort signal.** The contract's fourth Forbidden Action asks that an upload "allow
   cancel"; `createHubClient` takes a base URL, a token and a `fetch`, and `POST /v1/parse` has no cancel route, so
   the screen's cancel removes the row and says the hub may still finish the import. Recorded so a later unit that
   adds request cancellation does not read the current behaviour as an oversight.
3. **`SUPPORTED_IMPORT_MIME_TYPES` is a second copy of a list the repository already has.** F§5.4's formats are
   named in `packages/core/src/parsers/dispatch.ts`'s own tables, but that entry is the Node-only parser entry
   (`@lectern/core/parsers`, which `scripts/check-isomorphic.mjs` keeps out of the isomorphic one), so importing it
   from the app would pull Node-only parsers into the Metro bundle. The six strings are therefore declared in
   `apps/android/src/import/import-service.ts`, matching `apps/desktop`'s watcher's own table and the DOCX type
   verbatim.
