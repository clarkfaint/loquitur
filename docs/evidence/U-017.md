## 3. Architecture notes
The adapter is one function, `createPiperEngine({ baseUrl, fetch?, timeoutMs? })`, answering `F§6`'s `TtsEngine`
with `id: 'piper'`, and two private helpers: a single request path with a deadline, and a reader per answer kind.
The base URL is configuration; a trailing slash is normalized away before the two paths are built.

**Voice list.** `GET {baseUrl}/voices` is read as JSON and validated. Each entry becomes `F§6`'s `Voice`:
`id = voiceIdFor('piper', name)`, `engine = 'piper'`, `engineVoiceId = name`, `name = name` (the service gives no
display label of its own), and `lang` = the text in front of the name's first `-` or `_`, so `en_US-lessac-medium`
is an `en` voice. No voice list is held in the file.

**Synthesis.** `POST {baseUrl}/synthesize` with exactly `{ text, voice, length_scale }`, where `voice` is the
engine voice id and `length_scale` is `1 / synthSpeed` — Piper's own unit of duration, so a doubled speed is a
halved `length_scale`. The answer is bytes, not JSON: they are wrapped as a `Uint8Array`, and the duration is
read out of the container's own `fmt `/`data` fields, because Piper times no word. `mime` is `audio/wav` and
`engineTokens` is `null` (the contract's *Forbidden Actions* forbid fabricating timestamps).

**Failure mapping.** One error type carries `code: 'ENGINE_UNAVAILABLE'` for every way a call can fail: a service
that cannot be reached, a non-2xx answer, a body the JSON reader refuses, audio with no readable duration, a
voice list that is not a list of names, and the deadline passing. Each message names the URL and the reason, so
the hub can report which backend is down rather than only that something failed.

**Deadline.** The default is 30 s, overridable per engine. The request carries an abort signal a real transport
uses to drop the socket, and the call *races* the answer against the deadline, so a transport that ignores the
signal still cannot hang the caller; the abandoned request is caught, because nothing is waiting for it.

**Isomorphism.** The module imports nothing from Node — it is reachable from the hub, the browser, the extension
and the desktop app — so it holds no `piper` process and no ONNX model (the contract's first two *Forbidden
Actions*), and it speaks to exactly two endpoints. `lib` is the target alone (`ES2022`), which declares neither
the timers nor the abort primitive, and R10 forbids the typings package that would; each host global this file
uses is therefore declared at module scope with the signature it actually uses, and the host's `fetch` is found
through `globalThis` and typed by the adapter's own request/answer pair, which is what lets an operator inject
one and a test inject a stub.

## 4. Lectern design
- [DESIGN] `POST /synthesize` with `{ text, voice, length_scale: 1 / synthSpeed }` and nothing else, `GET /voices`
  for voices, and no third endpoint — `F§6`, and the contract's second *Forbidden Action*.
- [DESIGN] `length_scale` is implemented verbatim, with no clamp: `F§6` bounds Kokoro's engine speed (0.25–4.0)
  and states no range for Piper. Section 7 proposes the wording that would settle it.
- [DESIGN] The duration is `readWavDurationMs(audio)` over the returned bytes — `F§6` ("Duration is computed from
  the WAV header") — so the reported duration and the container's own length are the same number by construction.
- [DESIGN] `engineTokens` is always `null`; the adapter never derives timings from text or audio — `F§6` and the
  contract's third *Forbidden Action*. (The hub aligns estimated timings, `F§5.6(b)`.)
- [DESIGN] Voices come from the service, never from a constant: `F§6`. The envelope is read as either a bare array
  or an object holding the entries, and an entry as either a bare id or an object carrying `name` — the two
  shapes `F§6` leaves open — and an entry with an empty name is refused rather than mapped to `piper:`.
- [DESIGN] `id = 'piper'` and `id = piper:<name>`, via `voiceIdFor` from U-015, so `F§6`'s identifier form is used
  rather than re-spelled.
- [DESIGN] `lang` is the language the service's own name prefixes it with (`en_US-lessac-medium` → `en`), and the
  display name is that same engine voice id, for want of any label the service provides — the reading `F§6`'s
  Kokoro adapter took with `af_heart` (U-016). Section 7 proposes saying so.
- [DESIGN] One `PiperEngineError` with `code: 'ENGINE_UNAVAILABLE'` covers unreachable, HTTP error, unreadable
  JSON, unreadable WAV and deadline — `F§6` names one engine-state failure, and `F§7.2` reports it as a state.
- [DESIGN] One request path with a 30 s default deadline, an abort signal and a race, so a transport that ignores
  the signal cannot hang a reader.
- [DESIGN] The package barrel gains one line, `export * from "./piper-engine";`, in the position Biome's import
  order wants (between `./mp3` and `./registry`) — §5's append-only rule, verified read-only in section 6.1.

## 7. Deviation proposals
1. **The delivered test file is outside the package's typecheck program, and R10 keeps it there.** The package
   `tsconfig.json` excludes `src/**/__tests__` (U-006's operator patch), so `pnpm --filter @lectern/core-tts run
   typecheck` never compiles this unit's test file; probed with `exclude: []`, that file reports six `TS2591`
   errors for `node:http` and `Buffer` because `@types/node` is not installed and R10 forbids installing it (see
   section 6.1). This is the host's documented shape, not a defect of this unit. Proposal: state the program
   boundary in `F§2.3`/§7 explicitly, or add `@types/node` to `F§2.3` for the packages whose tests read fixtures
   and serve stubs.
2. **`F§6` fixes Piper's `/voices` endpoint but not its answer.** The adapter therefore reads either a bare array
   or an object holding the entries, and an entry as either a bare id or an object carrying `name`. Proposal: say
   which envelope a Piper service is expected to answer, and whether an entry may carry a display label and a
   language, so `name`/`lang` need not be derived from the engine voice id.
3. **`F§6` states no range for Piper's engine speed.** Kokoro's is bounded at 0.25–4.0, while Piper's sentence
   gives only `length_scale: 1 / synthSpeed`; a `synthSpeed` of 0 would put `null` in the request body, because
   JSON has no `Infinity`. Implemented verbatim, with no clamp. Proposal: state a floor (or a range) for Piper.
