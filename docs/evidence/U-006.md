## 3. Architecture notes

No target was inspected, so this section records the shape of the extraction this unit builds rather
than anything observed about another product.

**One document, two extraction paths.** `parseHtml` parses the given string once with linkedom's
`DOMParser` and then asks Readability what the article is. Readability answers with the article *node*
(the `serializer` option is what makes it a node rather than an HTML string), and that node is mapped
directly; a second trip through linkedom's parser is avoided, which matters because that parser treats
a fragment differently from a document (section 2). When Readability answers `null` — its
`charThreshold` default of 500 characters means a thin or unstructured page is no article — the
document's own text is mapped instead, which is the fallback F§5.4 names.

**The mapping is a shallow document-order walk.** Each of `h1`–`h6`, `p`, `li`, `blockquote` and
`figcaption` becomes exactly one block and the walk does not descend into it, so nesting cannot
duplicate text. Everything else is either a container that ends the block being built and starts a new
one, an inline element whose words join the block around it, a word break, or one of the four elements
whose content is never prose. That single rule covers both F§5.4 cases: a document with structure maps
its headings, paragraphs, list items, quotes and captions in order, and a document with no structure
maps its block-level text container by container.

**What furniture means here.** A page's `nav`, `aside` and `footer` are not deleted by the walker the
way `script` and `style` are; they are simply outside the article Readability extracts. On the fallback
path the whole `body` is prose, per F§5.4's wording ("all block-level text under `body`"), so the
furniture of a page with no article is read — which is the behaviour the contract's test pins, since
that test's subject is the fixture article.

## 4. Lectern design

- [DESIGN] `parseHtml` asks Readability for the article *node* (`serializer: (node) => node`) instead of its
  serialized HTML, and maps that node in the tree it came from — follows F§5.4 ("Uses Readability on a
  linkedom document") and keeps the walker's input a real element of a real document.
- [DESIGN] The fallback root is the `body` **when it holds text**, else the root element. linkedom gives a
  fragment an empty `body` (section 2), and a fallback that returns nothing for a fragment would silently
  lose a document's prose — follows F§5.4's "falls back to `body`" with the one amendment needed to keep a
  fragment readable.
- [DESIGN] `head`, `script`, `style`, `template` and `noscript` are never read. The contract's test requires
  that no block carries `script` or `style` text; a `head` carries a title, not a sentence.
- [DESIGN] The four container/element decisions above are expressed as three sets and one map (headings by
  level, block tags by kind, block containers, word breaks) rather than as tag comparisons inside the loop,
  so the mapping rule is declarative and one place decides a tag's role — follows AGENTS.md §7 (types and
  names from `features.md`; `BlockKind` comes from `src/model.ts`, `RawBlock` from `src/builder.ts`).
- [DESIGN] `mapElementToRawBlocks` takes the DOM `Element` interface, which is what the contract's signature
  says, and reads only `localName`, `childNodes` and `textContent`. linkedom's elements are a second
  implementation of that interface; `parseHtml` is the one place that converts, so the conversion is visible
  once instead of at every call site.
- [DESIGN] `opts.url` inserts a `<base href>` before extraction, when the document has none and the address
  parses as a URL. F§5.4 keeps no link data in a `RawBlock`, so this is the option's only honest effect: it is
  what makes the document's relative references resolvable while Readability rewrites them. A malformed
  address is ignored rather than fatal — follows F§5.4 (the option) and AGENTS.md §7 (validate external input;
  a bad address must not cost the reader the text).
- [DESIGN] `ParsedHtml.lang` is `string | undefined`: the article's language, else the document's declared
  language, else `undefined`. The empty string is not a language, and F§5.1's default of `"en"` belongs to
  `buildDocument`, which applies it when the caller passes no language.
- [DESIGN] The parsers stay behind `@lectern/core/parsers` and are not re-exported from
  `packages/core/src/index.ts`, which the contract's forbidden actions require and
  `scripts/check-isomorphic.mjs` enforces.

- [DESIGN → contract] **The blocker, and two repairs for it.** `pnpm --filter @lectern/core run typecheck`
  cannot exit 0 for this unit as specified: the program that `packages/core/tsconfig.json` describes must
  contain `src/parsers/**`, which means (a) linkedom's shipped declarations — 131 errors under TypeScript
  7.0.2's DOM lib — and (b) the required test file's `node:fs` / `node:module` imports, which have no types
  on this host. Neither is repairable from the four files this unit may create (section 6 records the three
  attempts), and the two files that could repair it are read-only for the unit: `packages/core/tsconfig.json`
  (not in this contract's outputs, not in its patch scope) and `tsconfig.base.json` (governance).
  1. *Patch this contract's patch scope to include `packages/core/tsconfig.json`* with the note "set
     `skipLibCheck: true` and exclude `src/parsers/__tests__/html.test.ts` from the program". Measured in this
     session: with exactly that, the whole fixed command exits 0 — 9 tests pass, `tsc` reports nothing,
     `check-isomorphic.mjs` is clean. The exclusion costs no coverage: vitest erases types and runs the file
     as written, and the other four `.ts` files of the unit stay in the program.
  2. *Set `skipLibCheck: true` in `tsconfig.base.json`* and name, in each contract whose type-check program
     contains a `node:`-using test file, that file under a stated program boundary. This is the wider fix: it
     is the same wall for every later package that consumes a third-party `.d.ts` (U-005 already recorded the
     `minimumReleaseAge` one), and `tsconfig.base.json` is the one place that can state a repository-wide
     compiler boundary.
  Recommendation: option 1 for this unit (smallest change, keeps the type-check program honest about the
  unit's own modules) together with option 2's second half for the `node:` imports, which are not
  defect-specific: a *stated* program boundary per package is the convention the U-002 precedent already
  established by hand.
- [DESIGN → contract] `parseHtml`'s `opts.url` has no observable effect on a `RawBlock`, because F§5.4 keeps
  no link data in one. This unit therefore gives it the one real effect a URL has while parsing — the
  document's base address, which is what Readability resolves relative references against — and pins that
  behaviour with a test. Proposal: state the option's purpose in F§5.4, or move it to the unit that first
  needs an absolute link (U-032), so a later unit does not read it as an unimplemented field.
- [DESIGN → contract] pnpm 12.18.0's `minimumReleaseAge` policy would record this unit's installs as an
  exemption in `pnpm-workspace.yaml`, a path §5 makes read-only; U-005 recorded the same proposal. This unit
  installs with the policy's exemption reverted, so `pnpm-workspace.yaml` stays byte-identical to its
  committed content, and every `pnpm` invocation prints the policy error and a `[WARN]` line that is not a
  failure of the command. Proposal: settle the policy once (relax `minimumReleaseAge`, set
  `verifyDepsBeforeRun: false`, or add `pnpm-workspace.yaml` to the guard's always-allowed set).
