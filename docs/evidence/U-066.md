## 3. Architecture notes

**The archive (one `tar.gz`, three kinds of member).** `lectern.db` — a snapshot taken with the online backup
API, never the live file and never its `-wal`/`-shm` siblings; `library/**` — F§8.4's document files, which is
where F§5.9's models and originals live; `manifest.json` — `{ createdAt, schemaVersion, files }`, where
`schemaVersion` is `SCHEMA_VERSION` (`apps/server/src/db/migrations.ts`, the highest migration this build
applies) and `files` is every payload path the archive carries, sorted. `tts-cache/**` is a member **only** when
the request asks for it (`?includeAudio=1`); the token, `infra/.env`, OCR language data and anything else under
the data directory are never members, because they are never named.

**How the snapshot gets into an archive named `lectern.db` without a staging copy.** `tar.create` takes paths
relative to one `cwd`, so the snapshot is written *inside* the data directory under a serial name
(`.backup-<n>.db`) and `manifest.json` beside it (`.backup-<n>.json`), and the archive's `onWriteEntry` hook
renames exactly those two entries — the hook's documented use ("if any fields on this entry are changed, then
these changes will be reflected in the entry that is written"). The library is therefore streamed from where it
already is: no second copy of the documents is made, and the two temporary files are removed when the stream
ends, errors, or is destroyed. `portable: true` keeps `/`-leading paths and drive letters out of the header.

**Restore is three read-only passes, then one write.** (1) `tar.list` enumerates every entry and refuses the
archive outright if any path is absolute, contains a backslash or a `.`/`..` segment, or is any type but `File`
or `Directory` — so a symlink entry (which could redirect a later write through itself) is refused before
anything is written, and tar's own `..` protection is a second layer rather than the only one. (2) The manifest
is extracted **alone** into an operating-system temporary directory, parsed, validated against
`BackupManifestSchema`, and refused unless its `schemaVersion` is this build's; the temporary directory is
removed in a `finally`. (3) Every other entry's path is compared with the manifest's own `files` list — an
archive that carries a file its manifest does not describe, or omits one it does, is refused — and only then is
`tar.extract` run with a filter that admits exactly the vetted paths, into the target directory. A refusal at any
of the three passes leaves the target directory **empty**, and a target that already holds anything is refused
before the first pass: nothing is ever restored over, and nothing is restored automatically.

**Pruning is per cache entry, not per file.** F§7.3's cache is a directory shard per chunk id holding
`<chunkId>.<mp3|wav>` and a sibling `<chunkId>.json`; an *entry* is those files grouped by chunk id, and an entry
is old when the **newest** of its files is older than the cutoff — so a pair is never split and a stale audio
file beside a fresh sidecar is kept. Files are removed together, empty shard directories are left where they are
(removing a directory would risk the entries it still holds), and the report carries the entry count, the removed
count and the bytes freed. `--dry-run` computes and prints all three and removes nothing.

**The compose profile.** `llm` stays the profile name F§12 names. The service is `ollama/ollama` pinned to a
release tag (`0.13.0`), publishes no host port, and is reachable on the compose network alone — which is what the
contract's *Forbidden Actions* require. The hub's `LLM_BASE_URL` takes that service's address as its default
(`http://llm:11434/v1`), exactly as `KOKORO_URL` names the always-on engine's service; AI stays off until
`LLM_MODEL` is set as well, because F§7.1 makes both variables the switch.

## 4. Lectern design

- [DESIGN] The backup snapshots through the database's **online backup API** and never copies the live file
  (the contract's *Forbidden Actions*); the snapshot is a file the hub then archives, so a backup taken while the
  hub is serving is consistent (F§12).
- [DESIGN] Only the paths F§8.4 and F§7.3 define are ever added to an archive — the database file, `library/`,
  and `tts-cache/` when asked for — so the token, `infra/.env` and OCR language data cannot be members (F§11,
  the contract's *Forbidden Actions*).
- [DESIGN] `?includeAudio=1` is the only value that adds the cache; an absent or unrecognized value leaves it
  out, so a mistyped query can never widen a backup (F§7.3).
- [DESIGN] The manifest is written by the route and validated by the restore command, and both read the same
  `BackupManifestSchema` from `apps/server/src/routes/admin.ts`, so the producer and the consumer of the format
  cannot drift.
- [DESIGN] Restore refuses a target that is not empty, a manifest that is not this format, a schema version this
  build cannot read, an entry path that could escape the target, and an archive whose payload disagrees with its
  own manifest; it writes nothing in any of those cases (the contract's *Forbidden Actions*).
- [DESIGN] Neither the manifest's `createdAt` nor the prune's cutoff is read from a hidden global: the route
  stamps the manifest from the host clock (the hub holds no clock seam in `context.ts`, which this unit may not
  patch), and `pruneCache` takes `now` as an argument, so the tests pin every decision to an injected instant.
- [DESIGN] The prune's `LECTERN_DATA_DIR` is read exactly as F§7.1's table reads it (default `./data`), and the
  command needs no token: an operator prunes with `LECTERN_DATA_DIR` set and nothing else (F§7.1).
- [DESIGN] Both commands print what they did and set an exit code: usage and refusals go to standard error with
  a non-zero code, so a deployment script can branch on it (F§12).
- [DESIGN] The compose `llm` service is pinned to a release tag and publishes no port (F§2.3's own rule for
  external services, F§12, the contract's *Forbidden Actions*).
- [DESIGN] `docs/operations.md` documents the deployment, the profiles, the private-network reach, the backup
  and restore commands, the prune and the upgrade path, and states plainly which of those run from the image and
  which run from a checkout (§7 (1)).

### 6.3 What the implementation measured: two defects, both fixed inside this unit's files

1. **A streamed reply must be returned or awaited by an async handler.** The first run of the unit's own suite
   failed four cases with `TAR_BAD_ARCHIVE: Unrecognized archive format`, and a probe of the route showed the
   reason: `200`, `content-type: application/gzip` and a **zero-byte** body, with
   `Error: Cannot call write after a stream was destroyed` on the tar stream. The handler had called
   `reply.send(archive)` as a statement; an async handler whose promise resolves with nothing finalizes the reply
   as it returns, which destroys the response stream before `tar` writes a byte of it. Measured side by side in
   one probe (bare Fastify, the same `Pack`): `return reply…send(pack)` → **110 bytes**,
   `reply.send(pack)` as a statement → **0 bytes**, `await reply.send(pack)` → **110 bytes**, statement plus
   `return reply` → **110 bytes**. The route now awaits the reply (`FastifyReply` is thenable,
   `types/reply.d.ts:95`), and the reason is written where the line is.
2. **The staged snapshot and manifest outlived the response.** The live check's own inventory of the data
   directory after two downloads showed `.backup-1.db`, `.backup-1.json`, `.backup-2.db`, `.backup-2.json` still
   in place: `tar`'s stream emits neither `close` nor `error` for a response that *finished*, so the cleanup hung
   off an event that never came. `createBackupArchive` now answers the cleanup beside the stream, the route
   discards it in a `finally` after the awaited reply, and the stream listeners stay for the case where a
   response is destroyed mid-read. Both archive forms now assert an empty staging trail in the suite
   (`(await readdir(dataDir)).filter((name) => name.startsWith(".backup-"))` is `[]`) and the live check below
   shows the same after two real downloads.

## 7. Deviation proposals

1. **`infra/Dockerfile` is not in this unit's *Patch scope*, and the image ships only the server bundle.** The
   contract's *Pass/Fail Verification Test* requires `apps/server/dist/restore.mjs` and
   `apps/server/dist/prune-cache.mjs` to exist and be non-empty, and `build.mjs` now produces them — but the
   runtime stage of `infra/Dockerfile` copies **one** file of the bundle
   (`COPY --from=build /src/apps/server/dist/server.mjs ./dist/server.mjs`), so a container built from this
   repository cannot run either command, and its `CMD` is the server alone. The two commands are therefore
   documented (`docs/operations.md`) as running from a checkout against the same data directory, which is what
   F§12's own second sentence allows ("or a copy of the volume while the hub is stopped"). Proposed repair
   (needs a patched contract, because `infra/Dockerfile` is read-only here): add
   `COPY --from=build /src/apps/server/dist/restore.mjs /src/apps/server/dist/prune-cache.mjs ./dist/`, or a
   `COPY --from=build /src/apps/server/dist ./dist`, so `docker compose exec hub node dist/prune-cache.mjs …`
   works.
2. **`apps/server/src/db/database.ts` is not in *Patch scope*, and `HubDatabase` declares no `backup`.** F§7.2's
   route and the contract's *Forbidden Actions* both require the **online backup API** and no copy of the live
   file; the API lives on `better-sqlite3`'s `Database` instance, which is exactly what `openDatabase` returns,
   but U-055's frozen interface names five members and not that one. `routes/admin.ts` therefore describes the
   one member it needs and casts once at that boundary, the shape this repository already uses for `linkedom`
   and for the native addon. The operator's session note anticipated this file *if it were in Patch scope*; it is
   not, so nothing was touched. Proposed repair: expose it where it belongs — add
   `backup(destination: string): Promise<{ totalPages: number; remainingPages: number }>` to `HubDatabase`, or a
   `snapshotTo(path: string): Promise<void>` accessor — in a patch unit, and delete this unit's cast.
3. **`infra/.env.example` already carried the commented `LLM_*` lines.** The contract's patch note says the
   example environment file "gains commented `LLM_*` lines"; U-022's file already carries all three F§7.1 names
   (`LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`) as commented lines, so the end state the note describes was
   already met. This unit changes **one comment** and no value: the `LLM_BASE_URL` line now says the hub's
   default already points at the compose `llm` service, because this unit gives that variable a default and a
   stale example would tell an operator to set something they need not set. Everything else in the file is
   byte-identical.
4. **"Not modified in `n` days" is read from the newest file of an entry.** F§7.3's cache holds an audio file and
   a metadata sidecar per chunk id, and the contract requires that the two are removed together and that only old
   entries go. An entry's age is taken as the **newest** of its own files' modification times, so an entry is
   removed only when both files are older than the cutoff, and a pair is never half-removed. Read the other way
   (either file newer ⇒ keep, which is this rule; or either file older ⇒ remove, which can drop a fresh sidecar)
   the same sentence gives a different answer. Proposed wording: say which file's timestamp decides.
5. **`?includeAudio=1` is the only value that adds the cache.** The contract writes the query as
   `[?includeAudio=1]` and F§7.1's flags are `0`/`1`. This route treats only `1` as yes and every other value —
   including an absent one and a typo — as no, so a mistyped query cannot widen a backup and reveal cached audio
   a caller did not ask to carry. Proposed wording: state that any other value means no.
6. **No clock seam exists for the manifest's `createdAt`.** F§7.2's manifest carries `createdAt`, and the hub's
   context (`context.ts`, frozen) hands a route no clock, so the route stamps it from the host clock. The tests
   assert the field's shape and never its value. Proposed wording: if a unit ever needs a deterministic manifest,
   name a clock seam in `context.ts`'s overrides.
7. **`dist/server.mjs` can only run where its externals are installed, and nothing says so.** `build.mjs` marks
   `better-sqlite3`, `@napi-rs/canvas`, `tesseract.js` and `pdfjs-dist` external, and the hub's bundle reaches
   `@lectern/core/parsers` statically through `context.ts`, so the bundle is linked to Node built-ins *and* to
   those packages the moment it loads. Only `pnpm deploy --node-linker=hoisted` — which the image's build stage
   runs — installs them where the bundle's own directory can see them, so `node apps/server/dist/server.mjs`
   from a checkout dies at link time with `Cannot find package 'pdfjs-dist'`. Measured both **with** this unit's
   files and **without** them (`git archive HEAD` → the same bundle → the same error), so it is U-022's design
   rather than a regression; the live check in §6.3 therefore runs the hub on its `tsx` entry. Proposed repair:
   say beside the bundle, in the operations document or in `build.mjs`, that the server bundle is an image
   artifact and that a checkout runs the hub through `tsx` or through a `pnpm deploy` tree. The alternative —
   making the parsers import lazy — is a change to a file this unit may not write.
