## 3. Architecture notes

Inspection is unavailable, so nothing here is a claim about the reference product. The state machine, the layout
hierarchy and the drag arithmetic below are what the contract and F§10.2 fix for Lectern, in this unit's own
terms.

### 3.1 State machine

The widget is a *view*: it owns no player state, and the only truth it draws is the last `PlayerSnapshot` it was
handed. Its own two pieces of state are whether it is expanded and whether it is mounted at all.

| Something happens | State it moves to | What the reader sees |
|---|---|---|
| the content script installs, `autoShowWidget` is on, the page has readable text, the origin is not disabled, the page is the top frame | **offered** (mounted, collapsed) | the pill, at its remembered position or the default corner |
| `autoShowWidget` is off and nothing is being read | **absent** | nothing |
| a snapshot arrives that is not `idle`/`ended` | **reading** | the pill carries Pause; the highlight is moving |
| the pill's expand control (or `Enter` on it) | **expanded** | the bar: compact `PlayerBar`, the speed control, collapse, "disable on this site" |
| the pill's play control, with no reading yet | **starting** → the player's first snapshot decides | the pill flips to Pause when the player says `playing` |
| the pill's pause control | unchanged (the player's `paused` snapshot re-renders it) | the pill carries Play; the highlight stops moving |
| the bar's collapse control | **collapsed** | the pill again |
| the bar's "disable on this site" | **disabled** (unmounted, host removed) | nothing on this site, on this page or any later one |
| the player reports `ended` or `idle` | collapsed, still mounted | the pill with Play |

The one transition that is not the widget's to make is the last: a snapshot is data, and the widget never
asserts a state the player has not published.

### 3.2 Layout hierarchy

Fixed-position host element, bottom-left of the viewport by default, in the light DOM but carrying an **open
shadow root**: `lectern-widget` (host) → shadow root → one root element that resets inheritance (`all: initial`)
→ either

- **collapsed pill**: one horizontal row of three controls — play/pause (~36 px square), the expand control, and
  the drag handle (a grip of six dots) — about 96 × 40 px; or
- **expanded bar**: a column — the compact `PlayerBar` (the transport group, the rate readout, the remaining
  readout, the progress strip) on its own row, then a row with the speed control (slider plus the five presets
  `1, 1.5, 2, 3, 4.5`), the drag handle, "disable on this site" and collapse — about 420 × 96 px wide.

The handle is a real `<button>`, so it is reachable by `Tab` and movable by the arrow keys; the whole widget is
keyboard reachable and nothing inside it is focus-trapped. Every string is Lectern's own wording.

### 3.3 Drag arithmetic (F§10.1's own control vocabulary, this unit's own maths)

`clampToViewport(position, size, viewport)` keeps the *whole* widget inside the viewport: `x` is pulled into
`[0, viewport.width − size.width]` and `y` into `[0, viewport.height − size.height]`, each bound falling back to
`0` when the widget is larger than the viewport (an inset widget has nowhere else to go), non-finite inputs
reading as `0`, and the result rounded to whole pixels so a fractional pointer delta cannot leave the host on a
half pixel. `nextPosition(start, delta)` is the pure translation the drag applies before clamping, which is what
makes "after a resize" testable without a browser: the same position is clamped into the new viewport.

**Timing.** The drag is pointer-event driven (`pointerdown` on the handle captures the pointer, `pointermove`
applies `nextPosition` + `clampToViewport` to the host's inline `left`/`top`, `pointerup` releases and persists).
Nothing is sampled on a timer, so the host follows the pointer in the same frame the event arrives in, and a
drag that never moves the pointer changes nothing.

## 4. Lectern design

- [DESIGN] **Form and corner (the contract forbids imitating the reference widget's shape, position or control
  arrangement, so these are chosen, not observed).** Default: **bottom-left**, 16 px from the left edge and 16 px
  from the bottom edge; collapsed as a **pill** whose controls read left to right: play/pause, expand, drag
  handle; expanded as a **bar above the same corner** carrying F§10.1's compact player bar and the speed control.
  A different corner, a different order and a different collapsed form from the reference product's, and recorded
  here because there is nothing to compare against.
- [DESIGN] **The widget's styles are two sheets inside the shadow root**: `widget.css` (imported with `?inline`)
  brings the widget's own layout and the `--lectern-*` token values on `:host`; `@lectern/ui-web/styles.css` is
  imported the same way and injected after it, so the compact `PlayerBar` and the speed control are the shipped
  components' own class rules. Page styles cannot reach in (shadow boundary plus `all: initial` on the root
  element), and the widget's rules were never in the page's DOM to leak out.
- [DESIGN] **Mount rules.** Mounted when *any* of these holds, and never otherwise: `autoShowWidget` is on and the
  page has readable text (U-033's `extractPageDocument` over the page, discarded — the text map the extraction
  built is the reading session's to keep, not the widget's); or the widget itself started a reading. Never in a
  frame (`window.top !== window.self`), never when `location.hostname` is in `disabledSites`. This unit's
  rehearsal measured what the third clause of the contract's own sentence ("always mounted once reading starts")
  does to U-035's frozen element-count case; §6.1 and §7 record it.
- [DESIGN] **The per-origin position lives in its own `chrome.storage.local` key**,
  `lectern.extension.widget-position`, holding `{ [origin]: {x, y} }`, validated field by field on read like the
  settings record is. F§10.2's settings list has no position field and `ExtSettings` is U-032's frozen module with
  no `Patch scope:` to edit it (AGENTS.md §5), so the widget keeps its own record; §7 proposes the wording.
- [DESIGN] **"Disable on this site" writes the settings record**, not a second list: `setSettings({disabledSites:
  […, location.hostname]})` through U-032's own `settings.ts`, and the widget unmounts. A later load reads the
  same list back and stays absent, which is what makes the case survive a reload.
- [DESIGN] **The widget's play control starts the reading the extension already knows how to start**: with no
  reading yet, it sends `ext/read-active-tab` (U-035's relay, the same path the popup and the `read-page` shortcut
  use), which makes the page's own reading session extract and hand over the document; the offscreen document
  loads the document and plays it (U-034's `readDocument` dispatches `play` itself), so the widget needs no second
  start path. Every other control leaves as `ext/command` — F§5.7's vocabulary, unchanged.
- [DESIGN] **The widget's own snapshot stream is a second `ctx.listen`.** The content script's context has one
  way to receive: `ctx.listen`, which is one more `chrome.runtime.onMessage` listener. The widget registers one
  and never asserts a position the player has not published; §2 records why a second listener is harmless here
  (the reply is discarded by the sender, and both listeners see the same message).
- [DESIGN] **The host element is positioned with an inline style** (`position: fixed`, `left`/`top`, `z-index`),
  because a page's own `*` rules apply to a light-DOM host element with higher priority than the shadow tree's
  `:host` rules; everything visual is in the sheets.

## 7. Deviation proposals

- **"Always mounted once reading starts" collides with U-035's frozen element count.** The contract's *Required
  File Outputs* for `mount.ts` say the widget is "registered in `contentFeatures` when `autoShowWidget` is on, and
  always mounted once reading starts"; U-035's frozen `e2e/highlight.spec.ts` asserts the page's light-DOM element
  count is identical before and during a reading it starts from the popup. Both cannot hold for a reading the
  widget did not start: the host element is a light-DOM element by the contract's own first *Forbidden Action*.
  This unit keeps U-035 passing and mounts on a reading the widget itself starts; the measured consequence is in
  §6.1. Proposed wording: "…and mounted the moment a reading is started from the widget."
- **The per-origin position has no home in the settings record.** `ExtSettings`
  (`apps/extension/src/settings.ts:14-31`) carries `autoShowWidget` and `disabledSites` and no position field, and
  `settingsFrom` drops every key it does not know, so a position written into that record would be erased by the
  next `setSettings`. `apps/extension/src/settings.ts` is U-032's frozen file and this contract lists no
  `Patch scope:` line, so the widget keeps its own `chrome.storage.local` key (§4). Proposed wording: name the key
  in F§10.2's extension list, or add a `widgetPositions` field to the record.
- **The compact `PlayerBar` wants numbers the snapshot does not carry.** `PlayerBarProps` requires
  `progressFraction`, `remainingMs` and `baseWpm`; `PlayerSnapshot` has no word count and no duration, so a widget
  that is not the view that holds the document cannot compute them. This unit passes `0`, `0` and F§5.6(f)'s seed
  `170` (`apps/web/src/reader/use-player.ts:96` is the precedent for the literal) and the compact bar's progress
  strip therefore reads empty and `0 min` — honest, but a readout rather than a measurement. Proposed wording:
  add the two counts to the snapshot, or document a compact variant that takes neither.
- **U-035's §2 note on `chrome.storage` in a content script is contradicted by measurement.** It records that the
  content script's `chrome` has no `storage` and that "nothing in the content script can read the settings
  record"; §2 here measures the opposite on the same host and browser (keys include `storage`, and a
  `set`/`get` round trip succeeded). No earlier unit's behaviour depends on the wrong reading of it, but a later
  extension unit that needs a stored value should not inherit it.
