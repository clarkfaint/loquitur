## 3. Architecture notes

Inspection is unavailable, so there is no reference behaviour to record. What the unit is built from is
`features.md`'s own description of this platform, quoted here in generic terms so the design below can be
read against it:

- **Screens (F§10.1):** a hash-routed SPA with `#/library`, `#/read/:docId`, `#/import` (`?url=` imports a
  link), `#/settings`, `#/mini`.
- **Import (F§10.1):** "Import by file picker, drag-and-drop, pasted text, or URL; all go through
  `POST /v1/parse`."
- **The parse route (F§7.2):** raw file bytes with `Content-Type` and an optional `X-Lectern-Filename`, or
  JSON `{ url }`, or JSON `{ text, title? }` → `{ document, anchors? }`. No multipart.
- **The records a library is made of (F§5.9):** `DocumentMeta` (`docId`, `title`, `sourceKind`, optional
  `sourceUri`, `folderId`, `addedAt`, `wordCount`, `sentenceCount`, `updatedAt`, `deleted`), `Folder`
  (`id`, `name`, `parentId`, `updatedAt`, `deleted`), `Progress`, and the `LibraryStore`/`BlobCache`
  interfaces quoted in section 5. Every mutation appends an `Op`; deletes are tombstones; `folderId: null`
  means "filed in no folder" and an absent filter means "every folder".
- **Identity (F§5.2):** a document's identity is its `docId`, a hash of its block texts — not its title and
  not its file name.

## 4. Lectern design

- [DESIGN] **Import is one path, and it is the hub's** (F§10.1's "all go through `POST /v1/parse`"). The
  browser holds no parser: a file's bytes are read with `File.arrayBuffer()`, a link is sent as `{ url }`,
  pasted text as `{ text, title? }`, and every answer is validated by `@lectern/api-contract`'s
  `ParseResponseSchema` inside `createHubClient` before the library sees it.
- [DESIGN] **A duplicate is answered, not written.** `importFile`/`importUrl`/`importText` answer
  `{ docId, duplicate }`; the store is asked for the metadata first, and a document the library already holds
  live is reported and nothing is written. Two different files whose text is identical therefore collapse
  into one document (F§5.2 hashes the text), and two documents that merely share a title do not.
- [DESIGN] **What is kept beside the records.** The original bytes go to blob key `orig/<docId>` and a paged
  source's anchors to `anchors/<docId>`, both through F§5.9's `BlobCache`; `originalKey`/`anchorsKey` are
  exported so the PDF page view (U-030) reads the same keys. Records are written before the bytes: a document
  with no cached bytes is merely one that has to be sent again, while cached bytes no list holds are
  invisible.
- [DESIGN] **A URL import keeps no original bytes.** The hub fetched the page, so this client never held
  them; the address is kept as `sourceUri` instead. A file's bytes and pasted text's bytes are kept, because
  the caller holds them. (Proposed wording in section 7.)
- [DESIGN] **Progress in a list is worked out from the metadata** (`documentProgress`), because F§5.6(f)
  counts words through the model and a list of a whole library cannot load every document's text. The figure
  is exact at a document's start and end and within one sentence in between; a reader screen that holds the
  model reports F§5.6(f)'s own number. (Proposed wording in section 7.)
- [DESIGN] **The list's filter and its sorts live in `@lectern/core`** (`buildFolderTree`,
  `filterDocuments`, `sortDocuments`) rather than in the screen, because F§10.4's Android app must draw the
  same library from the same records; the filter mirrors F§5.9's own `listDocuments` query exactly, so the
  store and the screen answer the same question the same way.
- [DESIGN] **Tree rules the contract does not state:** a deleted folder is skipped and its children become
  roots (nothing is lost by deleting something above it); a folder whose parent is not in the list is a root,
  which is what an orphan and a partially-read list both are; a parent chain that loops is drawn as roots
  rather than recursed into forever; roots and siblings are ordered by name without case.
- [DESIGN] **Sort orders:** `addedAt` newest first; `title` without case; `progress` furthest-read first,
  which is the question "what am I in the middle of". Ties break on title, then on `addedAt`, so a list does
  not shuffle between two reads of the same records.
- [DESIGN] **Deleting asks first.** Deleting a document is two presses — the confirmation is what writes
  F§5.9's tombstone through `deleteDocument`, and the document's own two blobs (`orig/`, `anchors/`) are
  deleted with it. Deleting a folder moves what was filed in it (its documents and its child folders) up to
  its parent and then tombstones the folder: a folder is a place, and deleting a place is not deleting what
  it held. (Proposed wording in section 7.)
- [DESIGN] **A move is an ordinary write.** Filing a document in another folder is `putDocument(meta, model)`
  with the new `folderId`, so it is stamped and replicated like any other change rather than patched in place.
- [DESIGN] **`?url=` imports once.** The extension's "Open in Lectern" hands a page over as
  `#/import?url=…` (F§10.2); the screen starts that import once on arrival and never again for the same
  address, because the query stays in the address bar.
- [DESIGN] **The screens inject their own rules.** `apps/web/src/app.css` belongs to U-027 and is frozen
  (R6), so each screen adds a `<style id="lectern-import-styles">`/`<style id="lectern-library-styles">`
  element in an effect — the pattern U-025 used for its `::highlight()` rules — written only in the tokens
  `@lectern/ui-web/styles.css` declares, so both screens follow the reader's theme.
- [DESIGN] **The library is read back after every write.** No action mutates a copy of the library in the
  page: each ends by re-reading the store, so what is on screen is what a reload would show.
- [DESIGN] **Route registration is an append.** `apps/web/src/routes.ts` (U-027, `(registry)`) gains
  `#/library` and `#/import` after its existing entry; the shell derives its navigation from the registry, so
  the two screens are reachable with no edit to the shell. `packages/core/src/index.ts` gains one export line.

## 5. API signatures relied on

No new dependency was installed (R10): this unit adds no package, so `pnpm-lock.yaml` and
`pnpm-workspace.yaml` are untouched and there is no third-party `.d.ts` to quote. None of the packages §7
names as quote-required (`expo-*`, `wxt`, `electron`, `pdfjs-dist`, `tesseract.js`) is used. The APIs relied
on are workspace packages, quoted from their sources as installed:

- `@lectern/api-client` (`packages/api-client/src/client.ts`) — the three parse forms, each answering
  `ParseResponse` after `ParseResponseSchema.parse`:
  `parseFile(bytes: Uint8Array, filename: string, mime: string): Promise<ParseResponse>`,
  `parseUrl(url: string): Promise<ParseResponse>`,
  `parseText(text: string, title?: string): Promise<ParseResponse>`.
- `@lectern/core` (`packages/core/src/store/types.ts`, F§5.9) —
  `putDocument(meta: DocumentMeta, model: DocumentModel): Promise<void>`,
  `getDocumentMeta(docId: string): Promise<DocumentMeta | null>`,
  `getDocumentModel(docId: string): Promise<DocumentModel | null>`,
  `listDocuments(q?: { folderId?: string | null; text?: string }): Promise<DocumentMeta[]>`,
  `deleteDocument(docId: string): Promise<void>`,
  `putFolder(f: Folder): Promise<void>`, `listFolders(): Promise<Folder[]>`, `deleteFolder(id: string): Promise<void>`,
  `getProgress(docId: string): Promise<Progress | null>`,
  and `BlobCache.put(key: string, bytes: Uint8Array, mime: string): Promise<string>` / `delete(key: string): Promise<void>`.
- `@lectern/ui-web` via `apps/web/src/services.ts` — `getStorage(): Promise<Storage>` (no hub needed) and
  `getServices(): Promise<Services>` (the hub client, rebuilt when the connection changes).
- `DocumentMeta`'s `sourceUri` is `exactOptional()` in F§5.9's schema, so `metaFor` builds the record
  field by field and adds `sourceUri` only when the document has one — a spread carrying an explicit
  `undefined` is refused by the schema at run time, not only by the compiler.

## 7. Deviation proposals

1. **F§10.1's import entry points are described, not listed.** The contract's library screen shows what
   F§10.1 names — file picker, drop zone, link, pasted text — and nothing else: no cloud-drive connector, no
   sharing link, no extension installer (the contract's *Forbidden Actions*).
2. **F§5.6(f) has no model-free progress fraction.** `documentProgress` estimates the words before a position
   from `wordCount`/`sentenceCount`, the two counts `DocumentMeta` carries, because a list cannot load every
   model. Proposed wording: "A list may show progress from the counts in `DocumentMeta`; exact figures come
   from `progressFraction` with the model in hand."
3. **F§5.9 does not say what deleting a folder does to what it held.** Chosen: children and documents move to
   the deleted folder's parent, then the folder is tombstoned. Proposed wording: "Deleting a folder moves its
   documents and its child folders to the folder's parent."
4. **F§7.2's `{ url }` form returns a document, not the page's bytes.** A URL import therefore keeps the
   address as `sourceUri` and no `orig/<docId>` blob, unlike a file or pasted text. Proposed wording that the
   original bytes are kept "when the caller holds them".
5. **pnpm's supply-chain policy prints above every step of the fixed command.** U-019 left
   `@fastify/cors@11.4.3` inside `minimumReleaseAge`, so each `pnpm` invocation prints
   `ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION` plus `[WARN] The install that runs before scripts failed …` and
   still exits 0. Nothing in this unit's diff touches the lockfile or `pnpm-workspace.yaml`; recorded, not
   repaired (R11).
6. **Three defects the rehearsal caught, none of them in the fixed command's own steps.** (a) A test
   expectation listed folder *names* while its helper printed *ids* — the test was wrong, and the helper now
   prints names. (b) `getByLabel("Text")` matched both the textarea and an enclosing region, because a
   string locator is a case-insensitive substring match; the pasted-text section is now headed "From a paste"
   and the helper's two field locators are `exact`. (c) Biome's `lint/correctness/usePlaywrightValidDescribeCallback`
   fires on a module-level helper named `describe`, which is now `outcomeOf`. Recorded because the same three
   traps will meet the next unit that adds a browser suite.
