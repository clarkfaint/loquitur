## 3. Architecture notes

**Unit extraction (`scripts/unit.mjs`).** `spec.md` is a flat sequence of unit blocks. Each block
starts at a line `### U-0NN — <title>` and ends immediately before the next `### U-` heading (or
at end of file), so extraction is a line scan with two markers, not a parse of the document's
structure. Inside a block there are three machine-readable facts the guards need:

- the identifier and title, both on the heading line;
- the dependency list on the `Depends on:` line — the earlier units are named there as `U-0NN`
  tokens, so the field is a set of identifiers in the order they appear;
- the *Required File Outputs* list, a bullet list in which every bullet **begins** with exactly one
  backticked path, followed either by `(registry)` or by an em dash and an explanation. Only the
  first backticked token of each bullet is the path; the rest of the bullet is prose that mentions
  other paths and must not be collected.
- a patch scope, when present, is a line whose label is `Patch scope:` and which contains
  backticked paths only; the human explanation is a separate `Patch notes:` line. A block without
  that line has an empty patch scope. Unit U-001 has none.

**Forbidden-content scanning (`scripts/check-forbidden.mjs`).** The scan set is every file the
repository tracks under `apps/`, `packages/`, `infra/` and `scripts/`. Findings fall into three
kinds, and a failure report must distinguish them because only two of the three are about a file's
*contents*:

- *content* findings, reported as `path:line`, for the reference product's name (any letter case)
  and for a fixed list of source strings;
- *path* findings, reported as the path alone, for a directory segment named `ios` and for file
  names that belong to an excluded platform;
- *manifest* findings, reported as `package.json` plus the offending dependency name, for banned
  dependency keys in any scanned `package.json`.

A dependency rule is a *name* rule, not a content rule: the only place it can fire is a manifest's
dependency field, so the same word appearing in a guard's own pattern table, or in a test fixture,
is not a finding. The notation in the contract distinguishes exact names from families
(`posthog*` is a prefix, `@stripe/*` is a scope), and the guard keeps that distinction.

**Self-reference.** Two guards must name the very strings they reject, and both are themselves
scanned. Every literal that would match its own rule is therefore assembled at run time from two
or more fragments, so no scanned file contains a contiguous match. That is a property of the
source text, not an exemption in the rule: deleting the fragments and pasting the whole word in
would make the guard report itself, which is the intended behaviour.

**Scope checking (`scripts/check-scope.mjs`).** The check is a set comparison with three inputs:

- *base*: walking back from `HEAD`, the first commit whose subject starts with `feat(U-` or
  `blocked(U-` **and** does not name the unit being checked. Its purpose is that the ledger-recording
  commit of the previous unit is the boundary of "work this unit did". When no such commit exists,
  the base is the empty tree, so every tracked file counts as changed;
- *changed*: files that differ from the base (staged or not) plus untracked files that are not
  ignored. Both halves matter: without the second half a brand-new guard script that nobody has
  staged yet would be invisible;
- *allowed*: the unit's own outputs and patch scope, the always-writable ledger and evidence files,
  the lockfile, any `package.json`, the two export-barrel shapes under `packages/*/src/`, and every
  path a lower-numbered unit marked `(registry)`.

A unit identifier that is not in `spec.md` must fail, because it means the allowed set cannot be
built at all.

**Isomorphism checking (`scripts/check-isomorphic.mjs`).** A graph walk. The entry is
`packages/core/src/index.ts`; from it the guard parses import specifiers, follows only the
relative ones, and visits each file once. Two things fail the walk: reaching a file under
`packages/core/src/parsers/` (the Node-only entry that the isomorphic boundary excludes), and any
module specifier that names a Node built-in, a DOM/React Native runtime, or an Expo package. The
entry does not exist yet in this unit, and an absent entry is reported as a notice with exit 0 —
the boundary is vacuously intact before the package exists.

**How the guards find the repository.** Each guard derives its root from its own location: the
directory that contains `scripts/`. A test can therefore copy a guard into a temporary tree and
run it there, which is what this unit's test suite does. No new command-line surface is invented
for testing.

- [DESIGN] The root manifest declares the four F§2.1/F§2.3 choices at the exact ledger versions — TypeScript 7.0.2, Turborepo 2.11.11, Biome 2.6.7, Vitest 5.1.0 — as root devDependencies, with `lint`, `typecheck`, `test` and `build` wiring to `biome check .` and to Turborepo tracks, and `private`, `name`, `packageManager` and `engines.node` fixed as the contract requires — follows F§2.1 and F§2.3; AGENTS.md R10 (a new dependency needs a stop-and-report).
- [DESIGN] `formatter.lineWidth` is 140. This is the smallest width at which the whole tree passes without touching a file this unit may not edit: `scripts/preflight.mjs` is owned by the `DONE` unit U-000, is not in this unit's patch scope, and holds lines up to 134 characters, so a narrower width would report a format error the unit is not allowed to fix — follows AGENTS.md R6 and §5.
- [DESIGN] The Biome configuration ignores every Markdown file in addition to the paths the contract names. Biome 2 formats Markdown, and the governors are read-only: `spec.md`, `features.md`, `AGENTS.md` and the ledger are precisely the files a formatter must not reflow — follows AGENTS.md §5 ("Everything else … read-only") and R12.
- [DESIGN] Generated paths are excluded through the repository's own ignore rules (`vcs.useIgnoreFile`), which is what the contract asks for, with `targets/` and `**/generated` excluded explicitly. `targets/` holds operator-supplied inspection artifacts that must never be checked or committed — follows AGENTS.md §3.1 and §5.
- [DESIGN] `scripts/unit.mjs` is the single reader of `spec.md`; `scripts/check-scope.mjs` imports its block parser instead of re-implementing it, so a wording change in a contract cannot mean two different things to two guards — follows AGENTS.md §2 (the guards must agree on what a unit's outputs are).
- [DESIGN] The three content guards exit non-zero when they cannot read their inputs: a missing `spec.md`, an unparsable `package.json`, an unknown unit identifier and an unknown argument are all failures, never silent passes — follows the contract's forbidden action ("Do not make any guard script exit 0 when it cannot parse its input").
- [DESIGN] The test suite runs every guard inside a temporary tree that contains a copy of the guard itself, so the guards' real code paths — including their own root discovery — are exercised, and no test touches the repository tree — follows AGENTS.md §7 ("Unit tests are deterministic") and the contract's test requirement.
- [DESIGN] Exit codes and messages are the only output of the guards; nothing is written to the repository by a guard, so `biome check .` and the guards cannot interfere with each other's state — follows AGENTS.md §2 Step 4 (the gates are independent).

## 7. Deviation proposals

- [DESIGN → contract] Turborepo sends anonymous usage telemetry unless it is disabled, and this
  contract fixes the `typecheck` script text as `turbo run typecheck`, so a switch cannot be added
  to the script without changing a string the contract pins. AGENTS.md §6 excludes tracking from
  Lectern's own code, which this does not violate, but the operator may still want
  `TURBO_TELEMETRY_DISABLED=1` in the environment or `turbo telemetry disable` once. Not acted on:
  a contract change would be needed. Proposal: state the expectation for build-tool telemetry in a
  later contract.
- [DESIGN → contract] The contract defines the forbidden scan set as *git-tracked* files, so a
  newly written file is invisible to the guard until it is staged. This unit stages its work before
  the official run, and the ledger records the commit, so nothing escapes; but a later unit that
