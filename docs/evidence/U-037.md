## 3. Architecture notes
Nothing is recorded in the contract's three topics. Per AGENTS.md §3.1 a missing target is not a blocker: the ports below are built from the contract's own wording and `features.md`.

- [DESIGN] Command surface: the four manifest `commands` U-032 already declares (`toggle-play`, `next-sentence`, `previous-sentence`, `read-page`) are the whole keyboard surface; each maps to one `ext/command` message, and `read-page` maps to the page-reading relay instead.
- [DESIGN] Context menu: two items with a fixed generic wording — one shown for a text selection, one for a page — created on install and routed to the active tab's content script.
- [DESIGN] PDF hand-off: the extension never fetches or parses a document. It recognises a PDF by URL shape alone and opens the web app's import route with the URL encoded as a query parameter; `file:` URLs and private-window URLs are refused rather than handed off.

## 4. Lectern design
- [DESIGN] `context-menu.ts` creates exactly two items on install and removes the previous set first, so a re-install or an update cannot leave duplicates behind; a click on either item resolves the active tab and relays a message to it, and a click with no eligibility is answered by the menu's own visibility rules rather than by code that guesses. Follows the contract's *Required File Outputs* and F§10.2's background row.
- [DESIGN] `commands.ts` is the mapping table from the four manifest commands to protocol messages, and it asks the session layer to start a reading for `read-page` only when the active tab has no reading yet. Follows the contract and F§10.2.
- [DESIGN] `pdf-handoff.ts` keeps detection, URL building and the handler in one file: `isPdfUrl` strips a query string and a fragment, lowercases the path and compares the extension; `handoffUrl` builds `{webAppUrl}/#/import?url=<encodeURIComponent(pdfUrl)>` with the web app URL's trailing slash trimmed first; the `ext/open-pdf` handler refuses with `NOT_A_PDF`, `LOCAL_FILE` (an `http(s)`-only rule) and `NO_WEB_APP` (no hub or web app configured) in that order. F§11 and the contract's *Forbidden Actions*.
- [DESIGN] `selection-feature.ts` names `startSelectionReading()` — U-035's existing selection path, exported from the content-side reading module this unit may not rewrite — so "Read selection" reuses one extraction path instead of a second one.
- [DESIGN] Operator resolution for Requirement (6): `apps/extension/src/widget/Widget.tsx` is frozen (R6, U-036). The error status banner for a failed reading is therefore mounted and updated by `selection-feature.ts` inside the widget's shadow root when `snapshot.error` is set — it appends one element of its own to the existing host's shadow root, marks it with `data-lectern-widget-error`, writes the error code and a sentence of its own wording into it, and removes it when the error clears. It reuses the widget's own `:host` token block for colour and type rather than shipping a new stylesheet, and it touches no file U-036 owns.
- [DESIGN] `e2e/full.spec.ts` drives the six numbered behaviours against the existing rig (`e2e/fixtures.ts`, `e2e/global-setup.ts`, `e2e/pages/article.html`) without editing any earlier spec.
