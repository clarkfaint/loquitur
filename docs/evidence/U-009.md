## 3. Architecture notes

**The conversion is the library's, and only one other part is read.** `convertToHtml` turns the package's
markup into HTML, and this module never looks at `word/document.xml` — which is the contract's *Forbidden
Action* and the whole point of the row. The one other part it reads is `docProps/core.xml`, and it reads
**only** that part: `unzipSync` is given a filter, so a package's images, styles, numbering and fonts are
never inflated. No macro is run (nothing is executed at all, and a `.docm`'s `vbaProject.bin` is simply never
opened) and no image is embedded (the mapping keeps text, and an `<img>` element is not one of F§5.4's
block tags, so it contributes no block).

**A DOCX keeps its title in its core properties, and the conversion cannot supply one.** `convertToHtml`
returns body markup alone (measured: no `core.xml` reference anywhere in the installed build, and no
`<title>` in the value), while the contract's signature requires a `title`. The properties part is the
document's own metadata, in the same sense the OPF is an EPUB's — the U-008 precedent for reading a control
file — and `dc:title` is where Word itself writes the title a user sets in the document's properties. It is
read as XML (the third MIME type linkedom's `DOMParser` declares) and matched on the **local part** of the
element name, because linkedom keeps the `dc:` prefix in the name and a colon in a selector throws.

**mammoth's output is a fragment, and a fragment has to be given a document to live in.** The value is a run
of block elements with no `html` and no `body`. linkedom parses such markup into a document whose root
element is the first element it met and whose remaining elements are its *siblings* at document level, and
its other entry point (`parseHTML`) gives an empty body — so either way the tree that a walker over
`childNodes` sees would hold one block and lose the rest. Wrapping the fragment in a minimal document before
parsing is what puts all nine elements under one body, and it is why the mapped blocks are the whole
document rather than its first paragraph.

**The article walker is deliberately not Readability.** A Word document is already one article: it has a
body, headings and lists, and nothing to extract. Running Readability over the converted fragment could only
discard a document that is short or unusually structured, which is exactly the failure U-008 recorded for a
chapter. `mapElementToRawBlocks` is therefore the only place block kinds are decided, as F§5.4's DOCX row
says.

**A `Title`-styled paragraph is prose.** Measured: mammoth warns that it does not recognise the style and
converts it to `<p>`, so the fixture's title is both the document's `title` metadata and its first paragraph
block. That is the library's conversion reported faithfully; suppressing it would mean inventing a
style-map rule the contract does not name, and dropping a paragraph the document actually contains.

**One refusal, taken before either library sees the bytes.** A legacy `.doc` is an OLE2 compound file, and
neither installed library recognises it as anything but a corrupt ZIP (measured: two unrelated errors). The
OLE2 signature is therefore checked first, and the parse fails with `UNSUPPORTED_FORMAT` before any
conversion is attempted. F§5.4's dispatcher sniffs `PK` + `word/document.xml` for DOCX, so a ZIP that is not
a WordprocessingML package never reaches this parser; a package whose ZIP mammoth rejects fails with
mammoth's own error, which is the library's diagnosis rather than a Lectern code the contract does not name.

## 4. Lectern design

- [DESIGN] `packages/core/src/parsers/docx.ts` exports
  `parseDocx(bytes: Uint8Array): Promise<ParsedDocx>` returning `{ rawBlocks, title }` — the shape the
  contract fixes, and F§5.4's "Every parser returns `RawBlock[]` … and metadata". The bytes are only ever
  read from; nothing is copied out of the caller's array and no `Buffer` is required, because the installed
  `openZip` accepts a `Uint8Array` (section 2).
- [DESIGN] The refusal is an exported `DocxParseError` carrying `code: "UNSUPPORTED_FORMAT"`, mirroring
  U-008's `EpubParseError` and U-006/U-007's error classes: F§5.4 names the code, and F§7.2's error envelope
  is `{ error: { code, message } }`, so the hub branches on the code rather than searching a message — and a
  caller can tell a refusal from a bug with `instanceof`.
- [DESIGN] `DOCX_MIME` is exported, as `EPUB_MIME` is, because F§5.4's dispatcher has to recognise the
  package's MIME type when it routes an upload. It is asserted by a test of its own so the export is not
  untested surface.
- [DESIGN] `title` is the package's `dc:title`, trimmed, and `""` when the package declares none — which
  leaves `buildDocument`'s own title rule (first heading, then the first 60 characters) as the last resort it
  already is. No title is invented from the first paragraph, and the parser never reports a title the package
  does not declare.
- [DESIGN] The fragment is wrapped in `<!doctype html><html><body>…</body></html>` before it is parsed, which
  is the only way the mapping sees every block (section 2) and keeps the delivered code free of a second tree
  walk or a hand-rolled block splitter.
- [DESIGN] `word/document.xml` is never opened by this module, and no image part is ever inflated
  (`unzipSync`'s filter), so the contract's three *Forbidden Actions* hold by construction rather than by
  inspection.
- [DESIGN] `packages/core/src/parsers/index.ts` gains one export line, inserted where the standing lint
  gate's `organizeImports` wants it (`./docx` sorts before `./epub`, so it goes above the existing first
  line) — §5's append-only rule for a barrel, and the U-007 pitfall that a barrel line is an insertion
  rather than an append.
- [DESIGN] The module imports `mammoth`, `fflate` and `linkedom` and nothing else — no `node:` specifier —
  so the Node-only parser needs no ambient Node types in the package's type-check program, which is the
  barrier U-006 hit and the operator's patch removed for the tests' sake (section 5).
- [DESIGN] `packages/core/tsconfig.json` is **not** touched: the delivered test is under
  `src/parsers/__tests__`, which the operator's U-006 patch excludes from the program, so the test may read
  the fixture with `node:fs` while `tsc` still checks the delivered module — the contract lists neither
  tsconfig, so this unit could not have carried the exclusion itself.
- [DESIGN] The delivered test is the same shape as U-007's and U-008's: the fixture resolved through the
  `@lectern/fixtures` devDependency by name, the expectations read from `expected.json` and narrowed with
  zod, the refusal asserted on **class and code** (so a wrong failure cannot pass), and one test that runs
  the parser's blocks through `buildDocument` into a schema-validated model.

### What the rehearsal changed, and what it did not

The rehearsal produced **no failing test**: every one of the six passed on the first run in the scratch
workspace, and both steps of the fixed command were green before the evidence commit. Four of this unit's
decisions were nevertheless made by measurement rather than by assumption, and each one would have failed
**silently** — as a wrong block list rather than an error — if it had been guessed:

1. **The mapping root.** linkedom parses mammoth's fragment into a document whose root element is the first
   element met and whose remaining elements are its siblings, with no `body` at all; `parseHTML` gives an
   empty body. Mapping `documentElement` (the obvious reading, and the one `html.ts` uses for a whole
   document) would have yielded **one** block instead of eleven, and every test asserting a heading or a
   list item would have failed on a parser that looked correct.
2. **The title lookup.** `querySelector("dc:title")` **throws** in linkedom's XML tree
   (`Unknown pseudo-class :title`), and `querySelector("title")` finds nothing, because the prefix is part
   of the element's name. The lookup is therefore a walk over `querySelectorAll("*")` matched on the local
   part, which is what U-008 recorded for the OPF as well.
3. **The input shape.** The declarations name an `arrayBuffer` input that the Node build does not implement,
   so the type-safe-looking form would have failed at runtime with `Could not find file in options`.
4. **The title's source.** `convertToHtml` reads no core properties, so a parser that expected a title from
   the conversion would have returned `""` for every document.

The first two were found by a probe of the installed libraries, the third by reading the installed build,
and the fourth by a probe of the fixture — all before the evidence commit, which is what §3's "inspect
before code" asks for even when the contract's inspection target is `N/A`.

## 7. Deviation proposals

- [DESIGN → contract] **F§5.4's DOCX row does not say where a DOCX's title comes from, and the library it
  names cannot supply one.** The row reads "`convertToHtml`, then the HTML mapping", but the contract's
  signature requires a `title` and `convertToHtml` returns body markup alone (section 2). This unit reads
  `docProps/core.xml`'s `dc:title` — the part Word itself writes a document's title into, and the same kind
  of control file the EPUB row's OPF is. Proposal: name that part in F§5.4's DOCX row, so a later change to
  the parser (or the dispatcher) does not have to rediscover it.
- [DESIGN → contract] **The fixture's `Title`-styled paragraph is mapped as a paragraph, so the document's
  title is also its first paragraph.** mammoth does not recognise the style (it warns) and converts it to
  `<p>`, which this unit reports faithfully rather than papering over with a style map the contract does not
  name. Proposal: either say in F§5.4 that a Word `Title` style is body text, or name a style map
  (`p[style-name='Title'] => h1`) as the intended treatment — the two give different block lists, and the
  choice belongs to the contract.
- [DESIGN → contract] **`mammoth` ships CommonJS declarations with no `types` and no `exports` field, and
  they reference `Buffer`.** The import resolves only through the `main`-sibling fallback, and the declared
  `buffer: Buffer` input is a type this repository does not install — the same barrier U-006 recorded for
  `linkedom`'s declarations. Proposal: add `@types/node` to F§2.3, or state the type-check program's
  boundary (a package program that excludes the tests) as an explicit rule rather than as something each
  unit re-derives.
- [DESIGN → contract] **A package's parts other than the body and the properties are never read, and the
  contract's `Forbidden Actions` do not say so.** This unit passes `unzipSync` a filter, so images, styles,
  numbering and fonts are never inflated; "do not embed images" is then a property of the code rather than a
  promise. Proposal: record the filter as the intended implementation of that action, since the obvious
  implementation (unzip everything, then look at `word/document.xml`) reads every image in the package.
- [DESIGN → contract] **The contract's two test cases are a floor, not a ceiling.** This unit adds four:
  the MIME constant, the document-order kind list, the `buildDocument` integration and a package with no core
  properties. Proposal: name the last one, because "read the title from the properties" is easy to implement
  as "the properties are always there", and a document saved without them would then fail to parse at all.
