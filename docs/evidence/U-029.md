## 3. Architecture notes

Behaviour of the reference product is not described here, because nothing was observed. What follows is the
Lectern architecture this unit implements, read from `features.md` and the frozen units it builds on.

**F§5.7 — the eight-state player.** `idle → loading → ready → (buffering → playing ⇄ paused) → ended`, with
`error` reachable from any state. A `seek`, a `skip` or a `setVoice` clears the sink, repositions and refills,
resuming only where the player was playing; `setRate` refills only when a quarter-step change moves the
engine-side speed. This unit adds no second implementation: `createPlayerController` (U-013) is used exactly as
frozen, and the page owns nothing but the wiring around it.

**F§5.6(d) — the highlight clock.** `t = sink.current().positionMs + lookaheadMs`, sampled on
`requestAnimationFrame`; `lookaheadMs` is a setting, `0` on web. The page's active word is therefore whatever
`controller.activeWord()` answers, sampled per frame while audio is moving and read once per state change when
it is not — which is also what makes a restored position paint before playback starts.

**F§5.6(f) — progress.** `fraction = (wordsBefore(sentenceIndex) + wordIndex) / wordCount`, and remaining time
is `remainingWords / (baseWpm · rate)` minutes with `baseWpm` a running average seeded at `170`. Both come from
`@lectern/core`'s `progressFraction`/`remainingMs`/`updateBaseWpm` unchanged.

**F§10.1 — the reader and the keyboard.** `Space` toggles, `←`/`→` skip a sentence, `[`/`]` move the speed by
0.1, `Esc` closes a panel. The bus publishes the player's snapshot with the document's title and the active
word over `BroadcastChannel('lectern-player')`, and over the desktop bridge when the shell exposes it.

**F§5.9 — the records a reader owns.** Progress is one `progress` record per document and a bookmark is one
`bookmark` record, both written through the frozen `LibraryStore`, so both replicate to the reader's other
devices by the same LWW rule as everything else.

Layout, in the reader page's own words: a heading row carrying the document title, the two skip toggles and
the bookmarks control; the document text below it; the bookmarks panel beside the text when it is open; the
player bar pinned at the end. The mini page is one column — the title, then the compact bar.

## 4. Lectern design

- [DESIGN] `getDesktopBridge()` returns `null` unless `window.lecternDesktop` exists and carries the members F§10.3 lists, because the shell exposes it through `contextBridge` and a browser page has no such global; the accessor is the only place the bridge is reached (F§10.3, contract *Forbidden Actions* — no Electron import anywhere in the web app).
- [DESIGN] The bus transports raw payloads and the bus itself validates them: `PlayerBusTransport.post` sends one `PlayerBusMessage` and `subscribe` hands back *whatever arrived* (`unknown`), which `createPlayerBus` parses — a JSON string from `BroadcastChannel` or a structured object from the desktop bridge — against a zod discriminated union. A malformed payload is dropped, never applied (contract: all messages are zod-validated).
- [DESIGN] The two bus roles are enforced at the bus, not at the page: a host publishes and receives commands, a remote sends and receives snapshots, and the opposite call is a no-op. This is what keeps two tabs from fighting — the reader tab never executes a command that arrived over the bus as a snapshot, and the mini tab never publishes.
- [DESIGN] `PlayerBusSnapshot` extends F§10.3's `BusSnapshot` rather than replacing it: the desktop bridge's `publish`/`onSnapshot` keep exactly F§10.3's type (a wider object is assignable to it, so the bridge needs no cast), while the published message additionally carries the active word the contract asks for and the three figures the frozen `PlayerBar` needs in its compact variant (`progressFraction`, `remainingMs`, `baseWpm`). F§10.3's `BusSnapshot = PlayerSnapshot & { title }` has no word counts, so a remote cannot derive progress or remaining time at all, and the contract asks the mini page to render that bar.
- [DESIGN] Progress is written through the frozen store, at most once every 2 s while audio is moving, and immediately whenever the state leaves `playing`/`buffering` (pause, stop, end, error) or the page is hidden — the contract's own rule. The written position is `controller.activeWord()`, so a reload returns the reader to the word they were on, and the position is restored through F§5.7's `load` command carrying a `Position`.
- [DESIGN] `Esc` is not a `PlayerCommand`, so `commandForKey` answers `null` for it and the reader page handles it as "close the panel" (F§10.1 says `Esc` closes panels; F§5.7 defines no command for it). Every other shortcut of F§10.1 becomes a command.
- [DESIGN] A key with `Alt`, `Ctrl` or `Meta` held is ignored by `commandForKey`, and so is any key whose target is an `input`, `textarea`, `select` or a contenteditable element — the contract's "ignores keys while typing in a form field".
- [DESIGN] The reader page's own rules are injected as a `<style>` element carrying U-023's tokens, exactly as the frozen library screen does, because R6 freezes `apps/web/src/app.css`.

### 6.4 Design notes the run measured

The mock engine's own duration law makes the fixture's first sentence 1 380 ms of audio, so the second
sentence starts about 1.4 s in and the reader's poll for a sentence index above 1 succeeds well inside its
10 s budget; that is why the fixture's `TEXT` is six short sentences rather than prose. The host also
publishes its current state once a second beside every change, because F§10.1's bus defines no handshake for
a tab that opens after the reading began and the mini case opens its tab mid-playback — the case passed in
1.5 s, which is the beat and not a chunk boundary.


## 7. Deviation proposals

1. **F§10.3's `BusSnapshot` cannot serve the mini-player F§10.1 asks for.** `BusSnapshot = PlayerSnapshot &
   { title: string }` carries no word counts, so a remote tab cannot compute a progress fraction or a remaining
   time, while `@lectern/ui-web`'s frozen `PlayerBar` requires both as props in every variant. This unit keeps
   the bridge's type exactly as written and lets the published message carry a superset (`PlayerBusSnapshot
   extends BusSnapshot`), which the bridge accepts without a cast. Proposed wording for F§10.3:
   `BusSnapshot = PlayerSnapshot & { title: string; active: { sentenceIndex: number; wordIndex: number };
   progressFraction: number; remainingMs: number; baseWpm: number }`.
2. **There is no command for `Esc`.** F§10.1 gives `Esc` to "close panels" while F§5.7's `PlayerCommand` union
   has no member for it, so `commandForKey` answers `null` and the reader page handles the key itself. Proposed
   wording: state that panel handling is the view's own and not a player command.
3. **`fraction` still cannot read `1` at the last word** (already filed by U-012/U-014): F§5.6(f)'s
   `(wordsBefore + wordIndex) / wordCount` tops out at `(n−1)/n`. This unit implements the formula verbatim
   through `@lectern/core`'s `progressFraction` and asserts that behaviour rather than relaxing it.
