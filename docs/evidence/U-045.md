## 3. Architecture notes

Everything in this section was measured on this host or read out of the published toolchain in this session; the run itself is §6.

**What this unit is, and what it is not.** This is the first of the Android units, so the app it delivers is a shell: navigation, the hub connection, and the diagnostics registry. F§10.4's playback (`ExpoQueueSink` over `expo-audio`), reader, stores (`SqlLibraryStore`, `FileBlobCache`), import, share sheet and camera scanner belong to U-046–U-053, and none of their files or dependencies appears here. The registry file is marked `(registry)` so those units append to it rather than rewrite it.

**The navigation shape is the file system.** `expo-router` builds one route from every file under `app/`: `app/_layout.tsx` is the root stack (inside the safe-area and theme providers), `app/index.tsx` is the entry route and redirects to the settings tab, `app/setup.tsx` and `app/diagnostics.tsx` are stack screens, and `app/(tabs)/_layout.tsx` is a tab navigator with **no per-screen entry** — the group's files are its tabs, and each screen sets its own title and icon where it lives (`<Tabs.Screen options>` inside `app/(tabs)/settings.tsx`, the pattern F§10.4's "each screen sets its own title and icon" describes). A screen a later unit adds to the group appears in the bar without touching the layout.

**The connection is a small state machine, not a form.** States: *nothing saved* (`getConnection()` answers `null`), *saved* (both values validated and written through `expo-secure-store`), and *reachable* (a client built from the saved pair answers). The transitions are `setConnection()` (validate both values first, then write, then notify — so a bad deep link cannot leave half a connection behind) and the listener set behind `onConnectionChanged()`. The two stored values are `lectern.hub-url` and `lectern.token`; a half-written pair, an unparsable address or an empty token reads as *nothing saved* rather than as a broken connection.

The probe in the settings screen and in `hub-health` asks for **two** routes: `GET /healthz` and `GET /v1/voices`. F§7.2 exempts `/healthz` from F§11's token, so a probe on that route alone would report a hub with the wrong token as healthy; the voice list is the authenticated route that makes the answer mean "this reader can read with this connection" (the same reasoning the web app's connection check records).

**The diagnostics registry is the app's own conformance harness.** `apps/android/src/diagnostics/checks.ts` exports `checks`, an ordered list of `{ id, title, run() }`; a check never throws — a refusal is `ok: false` with a sentence a reader can act on. This unit registers `core-selftest` (F§5.2, F§5.3 and F§5.6's goldens, run on Hermes as well as under Node) and `hub-health`. The screen draws one row per check whose text is `PASS <id>` / `FAIL <id>` once the check has run, and `?autorun=1` starts the run on open so a later unit can verify a device with one `adb shell am start` intent.

**The theme is the stylesheet's values, converted once.** `apps/android/src/theme.ts` carries `@lectern/ui-web`'s palette verbatim (its light and dark blocks) and its rem-based measurements converted at the stylesheet's own 16 px root: space 0.25/0.5/0.75/1/1.5 rem → 4/8/12/16/24, radius 0.25/0.5/0.875 rem → 4/8/14, control 2.25 rem → 36, icon 1.25 rem → 20, progress 0.25 rem → 4, and its three font sizes (16 body, `0.875rem` 14, `0.75rem` 12). The font stacks are named as Android's generic families (`sans-serif`, `sans-serif-medium`, `monospace`), which is what the stylesheet's `system-ui` stack resolves to on the platform. No new colour or measurement is introduced.

**Host facts measured before the build.** `java -version` is OpenJDK 17.0.21 (F§13 asks for 17+), `adb` is at `/usr/local/bin/adb`, and `~/android-sdk` holds `build-tools/35.0.0`, `platforms/android-35`, `platform-tools`, `cmdline-tools/latest` and an accepted `licenses/android-sdk-license`. `ANDROID_HOME` is **not** exported into a non-interactive shell on this host (`echo "$ANDROID_HOME"` is empty, while the operator reports it set to `/home/user/android-sdk`), and `scripts/preflight.mjs`'s phase-4 check reads `process.env.ANDROID_HOME` — so the fixed command is run with `ANDROID_HOME=/home/user/android-sdk` exported in the shell, which is the operator's own value and not a change to the command. Measured and recorded: `node scripts/preflight.mjs --phase 4` exits 0 with 8 of 8 checks OK.

## 7. Deviation proposals

- The playback preferences the settings screen draws are held in the screen's own state. F§5.9's store — one `setting` record per field — arrives with U-046 (`apps/android/src/stores`), and this unit's file scope has no module for a preference store; a second place to keep them now would be a second thing to migrate. A patched contract could name a store file here if the operator would rather it landed early.
- `createClient()` is asynchronous (`Promise<HubClient>`), because it reads the secure store before it can build the client; a synchronous version would have to assume the connection is already in memory.
- The tab group's screens are auto-registered; `app/(tabs)/_layout.tsx` therefore carries no `Tabs.Screen` entry and each screen declares its own title and icon.
- The T-APK questions stay unanswered on this host. If the operator copies `targets/android/base.apk` in, the four questions (SDK levels, permission categories, exported components and the framework family `INFERRED` from class prefixes) can be answered in a patched unit without changing any file this unit ships.
- **The install step is the contract's, executed one level lower.** `npx expo install react react-native …` cannot install into this repository: it runs a bare `pnpm add`, which dies on the committed lockfile with `ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION` (`electron-to-chromium@1.5.486`), and this repository's every other `pnpm` call passes `--config.minimumReleaseAge=0 --config.strictDepBuilds=false`, which `expo install` has no way to forward (`npm_config_*` is ignored by pnpm). The install was therefore run as the same `pnpm add` with the exact spec list `expo install` had itself resolved from the installed SDK's `bundledNativeModules.json` — measured, not guessed, because it prints that list on failure. A patched contract could say so, or name the flags, rather than leaving the next executor to rediscover it. `npx expo install --check` verifies the result.
- **TypeScript stays at F§2.3's 7.0.2 even though Expo expects `~6.0.3`.** `npx expo install --check` exits 1 naming that one package; the ledger version is what the other eleven workspace projects compile with, and R10 forbids swapping a library version, so it is recorded rather than changed.
- **`docs/preflight.json` is rewritten by the first step of the fixed command and is not in AGENTS.md §5's always-writable set.** This is its third appearance (U-022, U-038, here): the file is restored with `git checkout --` before the standing gates. - **The gradle step changes the host as it runs.** With the licenses already accepted, AGP installs what the app's dependencies need: NDK 27.1.12297006, CMake 3.22.1, Android SDK Platform 37.0 and Build-Tools 36.0.0 went into `ANDROID_HOME` during this unit's runs (§6.3).
