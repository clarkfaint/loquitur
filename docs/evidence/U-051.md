## 3. Architecture notes

No behavioural evidence was gathered, so this section records only what F§5.5 and F§10.4 fix for Lectern.

- **The OCR line shape (F§5.5).** An engine answers with lines; each line carries its text, its bounding box as
  `[left, top, right, bottom]` in the engine's own pixel coordinates, and a mean confidence on the 0–100 scale.
  Lines below 40 are dropped. Lines are grouped into paragraphs by a whitespace gap wider than 1.5× the median
  line height, and every block a grouping produces is a paragraph — F§5.5 says nothing about recognising
  headings in a scan, so the grouping does not guess at one.
- **The camera path (F§10.4).** A multi-page document scanner produces one image per page; each page is read by
  an on-device text recogniser; the pages' blocks are ordered top-to-bottom and become one document with
  `source.kind = 'ocr'`. F§5.5 draws the boundary explicitly — *"Android does not use this pipeline for the
  camera. It runs ML Kit on-device and builds the document locally with `buildDocument`"* — so neither a scan
  nor a page image reaches the hub.
- **What a recogniser reports and what it does not.** ML Kit's per-line record carries text, a frame and corner
  points; it carries **no confidence**. F§5.5's line shape has one, and its 40-point floor belongs to the hub's
  tesseract adapter, so the on-device mapping states the only confidence it can honestly state.

## 4. Lectern design

- [DESIGN] **Camera only.** The generated manifest's extra permission is
  `android.permissions: ["android.permission.CAMERA"]`, on top of what the plugins already add (F§10.4:
  *"network, media-playback foreground service, notifications, wake lock, and camera only"*). No media-library
  read or write is requested, so nothing is saved to the gallery and no photo-library permission is asked for.
- [DESIGN] **The microphone is blocked, not merely unrequested.** `expo-image-picker`'s config plugin runs
  whether or not it is listed in `app.json` — `@expo/prebuild-config` auto-applies it as a legacy plugin — and
  its default branch *adds* `android.permission.RECORD_AUDIO`. `app.json` therefore configures it with
  `"microphonePermission": false`, the package's own switch and the only one that keeps the microphone out
  (F§10.4: *"`RECORD_AUDIO` and external-storage permissions are blocked in app config"*). §7 (1) records what
  this costs the contract's fixed command.
- [DESIGN] **One document per scan, pages numbered from 1.** `saveScan` assembles the pages and hands the model
  to `importDocumentModel`, so a scan is stored exactly as a parsed file is, with `source.kind = 'ocr'` and no
  `sourceUri` — a scan came from a camera, not from a file the reader can reopen.
- [DESIGN] **The title is the document's, not the camera's** — `Scan YYYY-MM-DD HH:mm` at the moment of
  assembly, unless the first block is a short heading, in which case F§5.1's own title rule names the document
  after its heading.
- [DESIGN] **Page images are temporary.** Each page's file is deleted once the document is saved, or once the
  reader abandons the scan; nothing but the model survives, so a scan leaves no photographs behind.
