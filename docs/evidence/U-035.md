## 3. Architecture notes

Inspection is unavailable, so nothing in this section is a claim about the reference product. The first part is
what the contract, F§10.2 and F§5.6 fix for *Lectern*; the second part is what this session measured about the
platform it runs on.

### 3.1 What the contract and the feature doc fix

- **Two highlights, no elements.** F§10.2 gives the content script two registered highlights,
  `lectern-sentence` and `lectern-word`, "styled from an injected stylesheet", and states the invariant this
  unit's case asserts: "No element is inserted into, or removed from, the page outside the widget host". The
  contract narrows that further — the rules go in through a *constructed stylesheet* on
  `adoptedStyleSheets`, and the sheet is removed when the highlight is cleared. Nothing is wrapped, restyled or
  inserted, so the page's element count and the article's `innerHTML` are identical before and during a
  reading.
- **Highlight positions are the model's own positions.** F§5.1 numbers a sentence globally and a word within
  its sentence, with character offsets into `Block.text` and `Sentence.text`; U-033's `TextMap` is what turns
  such an offset pair back into a DOM `Range` (`rangeFor(blockIndex, charStart, charEnd)`). So a highlight is
  arithmetic on the map and nothing else: sentence range = the sentence's own offsets, word range = the
  sentence's offsets plus the word's, both asked of the *same* map the extraction was built from. This is the
  reason the two ranges cannot drift from the text they paint.
- **The clock that drives the highlight is F§5.6's.** `t = sink.current().positionMs + lookaheadMs`, with the
  active word the last one whose start is ≤ `t` (`findActiveWord`, binary search, and `0` before the first
  start). The extension is a web platform, so F§5.6(d)'s default lookahead of `0` applies. The player is not in
  the content script: the offscreen document publishes an `ext/snapshot` and the content script applies it, so
  the content script owns no clock at all for the highlight — one snapshot in, one `show()` out.
- **Auto-scroll is `@lectern/ui-web`'s policy, not a new one.** U-025's `createAutoScroll({ clock, suspendMs })`
  is arithmetic over an injected clock: the active line may sit between 30 % and 60 % of the viewport, it is
  moved to 45 % once it leaves that band, and a manual scroll suspends the policy for four seconds before it
  resumes by itself. The content script supplies the clock (`performance.now`), a `scroll` listener that
  reports the reader's own scrolling, and the `Range.getBoundingClientRect()` of the active *word* as the line
  to keep in view.
- **Read-from-here is `Alt`+click only.** The contract forbids hijacking plain clicks and forbids consuming an
  event that does not map to a readable word, so the handler is: `altKey` (and no other modifier), a caret from
  the point, a block from the map, a sentence range and a word range from the model — `preventDefault` and
  `stopPropagation` only once a `{ sentenceIndex, wordIndex }` exists.
- **Where the message handlers live.** The contract says the `ext/read-active-tab` handler is "registered in
  `handlers.ts` and `features.ts`", but U-032's frozen `src/__tests__/messages.test.ts` asserts that the
  registry *as declared* answers `NO_HANDLER` for every type but `ext/get-status`, so an entry added to
  `handlers.ts` by name would break a `DONE` unit's test. The operator ratified the pattern U-034 established
  (`docs/evidence/U-034.md` §7): the feature registers its own entry at installation
  (`Object.assign(handlers, …)` inside `installReadActiveTab()`), `handlers.ts` stays byte-identical, and the
  startup list in `features.ts` — a `(registry)` path §5 keeps append-only — gains one line.

## 4. Lectern design

- [DESIGN] **`createHighlighter(textMap, model)`** (F§10.2, F§5.1): one object with `show(sentenceIndex,
  wordIndex)` and `clear()`. `show` resolves the sentence's own `charStart`/`charEnd` and the word's
  `sentence.charStart + word.charStart` through the map's `rangeFor`, registers the two ranges under
  `lectern-sentence` and `lectern-word`, and adds the constructed stylesheet to the document's
  `adoptedStyleSheets` on first use. `clear` deletes both registry entries and removes that sheet. The
  contract's signature names the map alone; `TextMap` (U-033, frozen) carries blocks, entries and `rangeFor`
  but no sentence boundaries, so the model is the second argument — filed in §7.
- [DESIGN] **Two deliberate looks** (F§10.2's "word is stronger than the sentence"): the sentence is a wash
  with a soft edge, the word a solid block with a dark ink edge. Both are literal colours in the constructed
  sheet rather than `var(--…)` tokens, because a content script paints on a page that has no token sheet of
  its own — the tokens U-023 declared exist only inside the Lectern app.
- [DESIGN] **`click-to-read.ts` maps a point to a position through the map, not through the DOM's text
  content** (F§10.2, F§5.1): the caret from `caretPositionFromPoint` (or `caretRangeFromPoint`) names a text
  node; the map's entries name the block that node belongs to; the block's sentences and words are then tested
  by range containment, which is exact across collapsed whitespace, nested inline elements and line breaks —
  offsets recomputed from the element's text would not be. A point in the whitespace between two words joins
  the word that starts at or after it, and a point outside every mapped block, in a chrome region, or in a
  field returns `null`.
- [DESIGN] **`reading-session.ts` owns the page's half of the reading** (F§10.2): `startPageReading(startSentence?)`
  extracts with U-033's `extractPageDocument`, builds the highlighter from the same map, and sends
  `ext/read-document`; `startSelectionReading()` does the same for a selection
  (`extractSelectionDocument`, `source.kind: "selection"`); `stop()` clears the highlight and tells the player
  to stop; `pagehide` stops a reading whose page is going away. An incoming `ext/snapshot` is the only input
  that moves the highlight, and the same message is what asks the auto-scroll policy for a target.
- [DESIGN] **Auto-scroll follows the word, suspends on the reader's own scroll** (F§10.1's policy, F§10.2's
  "auto-scroll"): the word's range rect is the line, the viewport is the band, and a programmatic scroll is
  not mistaken for the reader's — the scroll offset the last programmatic move landed on is remembered and
  ignored, which is U-025's measured behaviour (`scrollBy` raises exactly one `scroll` event).
- [DESIGN] **`contentFeatures: ((ctx: ContentContext) => void)[]`** (F§10.2, §5's registry class): the content
  script's startup list, the mirror of the service worker's `features`, with this unit's reading session as its
  only entry. The entry point builds the context, runs every feature, and answers nothing itself — the
  features register the messages they answer.
- [DESIGN] **`installReadActiveTab()`** (F§10.2): registers `ext/read-active-tab` in the router's registry at
  installation and binds the `read-page` command (`Alt+Shift+R`, U-032's manifest) to the same request, then
  appends itself to the background feature list. `handlers.ts` stays byte-identical, so U-032's frozen
  registry test keeps passing (the operator's ratification, §3.1).
- [DESIGN] **Top frame only, never on page load** (the contract's *Forbidden Actions*):
  `defineContentScript({ matches: ["<all_urls>"], runAt: "document_idle", allFrames: false })`, and nothing in
  the script starts a reading until a message arrives.

## 7. Deviation proposals

1. **`createHighlighter`'s second argument.** The contract lists `createHighlighter(textMap)`; `TextMap`
   (U-033, frozen) holds blocks, text entries and `rangeFor`, and no sentence boundaries, so F§5.1's global
   sentence index cannot be resolved to an offset pair from it alone. Implemented as
   `createHighlighter(textMap, model)`. Proposed repair: the contract's *Required File Outputs* line to read
   `createHighlighter(textMap, document)` — no other change.
2. **Registration at installation, already ratified.** The contract's `read-active-tab.ts` line says the
   handler is "registered in `handlers.ts` and `features.ts`". Registration happens in `installReadActiveTab()`
   and only the feature line is appended, because U-032's frozen `messages.test.ts` asserts the registry as
   declared refuses every other type (the operator ratified this pattern from U-034 §7). Proposed repair: the
   contract's wording to say "registered by its own `install…()` function; appended to `features.ts`".
3. **What `@lectern/ui-web` supplies.** The contract lists `createAutoScroll` among this unit's inputs, and it
   is used unchanged — the extension's own file adds what a browser needs (the `performance.now` clock, the
   `scroll` listener, the scroll offset the last programmatic move landed on) and no policy of its own.
   Recorded here only so the boundary is explicit: no auto-scroll arithmetic is re-implemented.
