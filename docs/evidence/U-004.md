## 3. Architecture notes

**The skip classifier is two independent passes over the same block list.** The first pass — footnotes —
needs no page arithmetic at all: a block whose text begins with `^\d{1,3}[.)]?\s` *and* whose
`fontRatio` is below 0.85 becomes `footnote`. The second pass — running heads and feet — is the paged
one and applies only when the document has at least three distinct page numbers. It runs in two sweeps
so that a key's tally is complete before any block is retyped: sweep one builds, for each
`band + key` pair, the set of distinct **pages** on which that key occurs in that band; sweep two
retypes a block only when its own pair's set satisfies `distinctPages × 10 ≥ pageCount × 6` (the
integer form of "at least 60%", so no float comparison decides a boundary case). The band is decided
per block from `yRatio` — `≤ 0.08` is the top band, `≥ 0.92` the bottom — and the pair is what keeps a
top line from being confused with an identical bottom line.

**Why the page *set* rather than a block count.** A page can contain the same furniture line twice (a
two-column layout, a repeated rule). Counting blocks would let one page satisfy 60% of the document by
itself; counting distinct pages cannot.

**The digit-substitution key** is `text.replace(/\d/g, "#")`, then whitespace collapsed to one space
and trimmed. Digits are the only characters substituted, which is exactly the discriminator F§5.4
names: `Page 1`…`Page 12` all become `Page #`, while `Chapter One` and `Chapter Two` stay distinct —
and, by design, so do `Chapter 1` and `Chapter 2` (they become the same key), which is a deliberate
over-match: a numbered running head is furniture. A block only ever inherits a band from its own
position, so the over-match can never move a body line.

**Block order in `buildDocument`.** Normalize → drop empties → classify skip → build blocks with global
sentence indexes → count → `docId`. Normalization is the only step that may change block text, and it
must run before `docId`, because F§5.2 hashes the *normalized* block texts; tokenization must run after
normalization for the same reason, since sentence offsets are offsets into `Block.text`. Classification
sits between them because it reads text (normalized, so that two spellings differing only in
non-breaking spaces compare equal) and writes only `kind`.

**Title precedence** is contract text, not inference: explicit `meta.title` wins; else the first
`heading` block's text; else the first block's first 60 characters. `lang` defaults to `en`, and
`source` is copied through untouched, both per F§5.1.

**Markdown is line-oriented, with a paragraph buffer.** A blank line flushes the buffer. A line that
opens a heading, list item or quote flushes the buffer first and then produces its own block; a
consecutive run of `>` lines accumulates into one quote block; every other line is appended to the
buffer and the buffer's lines are joined with a newline when it is flushed. Because role detection uses
anchored patterns on the raw line, `* emphasis *` in the middle of a sentence can never be mistaken for
a list, and an indented list marker still counts (leading whitespace is allowed).

**Inline stripping protects code spans first.** Code spans are lifted out into placeholders, the
emphasis / link / image / strikethrough patterns run on what is left, and the placeholders are
restored — which is what keeps `snake_case_name` intact instead of letting `_case_` be read as
emphasis.

## 4. Lectern design

- [DESIGN] `RawBlock` and `DocumentMetaInput` live in `builder.ts` and are imported **type-only** by `skip.ts` and `text.ts`; `builder.ts` value-imports `classifySkip`. Under `verbatimModuleSyntax` the type-only direction is erased, so there is no runtime cycle, and the contract's *Required File Outputs* stay exactly seven files — follows the contract's file list and AGENTS.md R5.
- [DESIGN] `classifySkip` returns a **new** array of blocks with only `kind` changed; it never removes a block and never sets a `skip` field on a `RawBlock` (which has none). `buildDocument` derives `skip` from the kind, so the model keeps furniture in place and the player is the only thing that omits it — follows the contract's *Forbidden Actions* ("Do not delete skipped blocks") and F§5.1 (`Block.skip`).
- [DESIGN] The footnote datum `fontRatio` is read as "font size ÷ the page's median font size", the same ratio F§5.4's PDF row uses to mark headings at ≥ 1.25×; `< 0.85` is therefore the small-font test verbatim — follows F§5.4.
- [DESIGN] Footnote classification does not require three pages; only the running head/foot rule does, because F§5.4 attaches the minimum to the page-repetition test and the footnote rule is stated per block. A paged document of two pages still marks footnotes.
- [DESIGN] The 60% test is `distinctPages × 10 ≥ pageCount × 6` over the page set of the `band + key` pair, with `pageCount ≥ 3`. Integer arithmetic avoids a float boundary case at 60% exactly, and the page set makes one page count once — follows F§5.4.
- [DESIGN] `stripCitations` returns a new string (never mutates, never touches the model's text) and only removes **fully numeric** bracketed runs, optionally comma/semicolon separated or hyphen/en-dash ranged; anything else in brackets is left alone. Runs of spaces/tabs left behind collapse to one and the result is trimmed — follows F§5.4's "the document text is not changed" and the contract's *Forbidden Actions*.
- [DESIGN] `playableSentences(doc, { skipFurniture })` walks blocks in document order and emits **global sentence indexes**; a skipped block contributes none when `skipFurniture` is true, and all of them when it is false (the default the settings layer will pass is `true`, per F§5.4, but the function has no default of its own so the caller's choice is explicit) — follows F§5.1/F§5.4.
- [DESIGN] `sentenceAt(doc, index)` returns the `Sentence` whose *global* `index` matches, and throws a `RangeError` naming the index when none does: the signature returns a `Sentence`, so absence cannot be represented as a value, and a silent `undefined` would be a lie about the model — follows the contract's signature and AGENTS.md §7 (no `any`, validated boundaries).
- [DESIGN] Headings require whitespace after the hash run (or end of line), and seven-or-more hashes is not a heading; `#hashtag` therefore stays a paragraph. F§5.4 names only `#`…`######`; requiring the CommonMark space is the reading that cannot corrupt ordinary text — follows F§5.4.
- [DESIGN] A `1.`-style marker is accepted with any digit run (`\d+[.)]`) and `-`/`*` with either a space or end of line; the marker itself is stripped and the remaining text is the block's text. Paragraph lines are joined with `\n` so that a hard-wrapped line keeps its break and the tokenizer sees it as whitespace — follows F§5.4.
- [DESIGN] `buildDocument` drops a block whose text normalizes to the empty string *before* classification and indexing, so `Block.index` is contiguous over the surviving blocks and no sentence range can be empty — follows F§5.2's normalization and F§5.1's `Block.index` (0-based, document order).
- [DESIGN] `src/index.ts` gains four export lines (`builder`, `playable`, `skip`, `text`) as sorted insertions between the existing lines, because §5 makes the barrel append-only but the standing lint gate sorts it — follows AGENTS.md §5.

## 7. Deviation proposals

- [DESIGN → contract] F§5.4's footnote rule has two arms: "in a font smaller than 0.85× the page median,
  **or** below a horizontal rule". `RawBlock` as the contract defines it carries `kind`, `level`, `page`,
  `text`, `fontRatio`, `yRatio` — there is no field that encodes "a horizontal rule was crossed", so the
  second arm is not expressible in this unit and is not implemented. Proposal: either add a boolean
  (e.g. `belowRule?: boolean`) to `RawBlock` and to the parser contracts that produce it, or delete the
  arm from F§5.4. Until then the font arm alone decides, which is why a footnote in body-sized type at
  the foot of a page is *not* marked here.
- [DESIGN → contract] F§5.4 says "a line whose text, with digits replaced by `#`, appears in the top 8%
  or bottom 8% of at least 60% of pages". A block without `yRatio` (any non-paged source, and any
  parser that supplies no geometry) can never be placed in a band, so it is never furniture; the
  contract is silent on that case. Proposal: state that furniture detection is geometry-dependent and
  that geometry-free sources carry no headers or footers.
- [DESIGN → contract] The minimum-3-pages clause means a two-page document can never have its running
  head marked, however obviously repeated it is. That is F§5.4's own limit and it is implemented as
  written; recorded so that the cost is visible if the operator wants a 2-page exception.
